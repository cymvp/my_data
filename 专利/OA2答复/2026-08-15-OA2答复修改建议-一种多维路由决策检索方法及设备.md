## 3. 说明书核对结果

已调取本申请公开文本 CN122388163A。

### 3.1 新增的权利要求特征有说明书支持，专利法第三十三条风险排除

本轮往权利要求 1 中新增的表述是"所述多维度结构化路由决策数据的各维度在同一推理上下文中相互交叉参考，在推理某个维度时动态利用其他维度的中间推理结果进行协同调整"。

说明书 [0025] 段原文：

> 本实施例的大语言模型作为核心推理引擎，经过大规模文本语料的预训练，具备了理解复杂语义与生成结构化输出的能力。大语言模型用于根据若干系统指令信息和用户查询文本，一次性生成多维度决策信息。大语言模型单次推理调用是指仅执行一次模型前向传播，从而避免了多次串行调用带来的延迟累积与资源浪费。而且，大语言模型在一次推理中同时完成多个不同路由决策维度的联合生成，各维度在同一推理上下文中相互交叉参考，例如大语言模型在推理某个维度时，能够动态利用其他维度的中间推理结果进行协同调整。这种联合生成与交叉参考机制，有效解决了分步多次调用中常见的上下文割裂、决策冲突以及信息利用不充分等问题，确保最终输出的多维决策在语义上保持内在一致，从而显著提升了路由决策的整体准确性与可靠性。

新增表述与该段记载逐字对应，修改未超出原说明书记载的范围。**这一项风险排除，不需要再处理。**

### 3.2 说明书里有两处可以直接引用的有利记载

**第一处，[0025] 段自带完整的技术效果因果链。**该段明确写明单次推理联合生成解决的是"分步多次调用中常见的上下文割裂、决策冲突以及信息利用不充分"，达到的效果是"确保最终输出的多维决策在语义上保持内在一致"，进而"显著提升了路由决策的整体准确性与可靠性"。

这一点的价值在于：技术效果如果只由代理师在答复中主张，审查员可以认为是事后补充的说辞；写在原始说明书里的记载则是申请日就已确定的事实。本轮答复应当直接援引 [0025] 段原文，而不是以论证的口吻重新表述。

**第二处，[0023] 段支撑维度之间存在耦合关系这个前提。**该段写明系统指令信息用于向模型说明"当前多路检索系统中各检索路径的基本特性、模型输出所需遵守的格式与取值范围，以及不同决策维度之间的依赖关系"。

这段有两个用处。一是"格式与取值范围"直接支撑上一轮已经被审查员回避、本轮仍然成立的论点，即系统指令信息是调用模型之前下发的输出约束，与对比文件 2 的结构化意图描述对象（模型解析之后的输出结果）方向相反。二是"不同决策维度之间的依赖关系"证明各维度相互耦合是本申请的原始设计前提，不是为了答复而临时提出的说法。

### 3.3 新发现的风险：说明书自身提到了效率

[0025] 段在讲单次推理时，除了语义一致性，还写了"从而避免了多次串行调用带来的延迟累积与资源浪费"。

审查员本轮的关键句是"**为了提高检索效率**，本领域技术人员容易想到大语言模型仅执行一次推理调用"。他完全可以引用本申请自己的说明书来印证这个效率论：既然申请人自己承认单次调用的好处是避免延迟累积和资源浪费，那么以提高效率为动机去合并调用就是本领域的常规优化。

**这一点必须在本轮主动处理，不能等审查员在驳回决定里提出来。**处理方向不是否认效率效果，而是把两种效果分开：效率提升是单次调用的附带结果，任何合并调用都能获得；语义一致性则不是，它来自各维度在同一上下文中交叉参考这一机制本身，把多次调用简单合并并不能得到。具体文字见第 4.1 节。

## 4. 代理稿的遗漏与建议补充的内容

代理稿事实准确，但最有力的三个论点没有提出，另有两处需要预防性处理。以下五节给出可直接采用的文字。

### 4.1 补充一：对比文件 3 构成反向教导

代理稿只说明了对比文件 3 是多步串联、与本申请不同，没有进一步指出该文件本身给出的是相反的技术启示。这两者分量不同：前者是"本申请与该文件不一样"，后者是"该文件自身正在往相反方向走"。

建议在区别技术特征（1）的论证之后插入以下内容。

> 除上述差异之外，需要特别指出，对比文件 3 不仅没有给出单次推理调用的启示，其自身的技术路线恰恰相反。
>
> 对比文件 3 说明书 [0062] 至 [0063] 段明确记载：若字段校验结果存在字段不匹配，将不匹配信息反馈至大语言模型并补充修正指令，重新生成 SQL 语句，从而获取最终的 SQL 语句。也就是说，对比文件 3 在生成环节主动设计了失败后再次调用大语言模型的机制。结合该文件 [0028] 至 [0033] 段记载的分词器、编码器、实体识别子模型、标签库匹配四步串联的意图解析流程，可以确认对比文件 3 的整体架构建立在多阶段、多次模型调用之上，并且把再次调用作为保证输出质量的常规手段。一篇通篇采用多次调用、并将失败重试写入技术方案的文件，无法给出应当仅调用一次的技术启示，其给出的是相反的启示。
>
> 审查意见认为"为了提高检索效率，本领域技术人员容易想到大语言模型仅执行一次推理调用"，申请人不认可。首先，该认定未说明理由，也未提供任何证据。其次，本申请说明书 [0025] 段记载的技术效果有两个层面：一是避免多次串行调用带来的延迟累积与资源浪费，二是各维度在同一推理上下文中相互交叉参考，从而解决分步多次调用中的上下文割裂、决策冲突与信息利用不充分问题，确保多维决策在语义上保持内在一致。前一个效果确实与效率有关，任何形式的调用合并都可能获得；后一个效果则不然，它来源于多个决策维度在同一推理上下文中联合生成、后生成的维度以已生成的维度为条件这一机制本身。
>
> 具体而言，本申请的各决策维度之间存在语义耦合关系，这一点在说明书 [0023] 段中已有记载，即系统指令信息需要向模型说明不同决策维度之间的依赖关系。查询意图类型决定检索范围的合理取值，检索范围决定各条检索路径的权重分配，查询文本中是否存在时间约束直接影响时间序列检索路径的权重高低。若分多次调用分别生成各维度，后一次调用只能获得前一次已经文本化的输出结果，无法获得其完整推理依据，同一查询就可能在不同维度上被解释成不同意图，产生互相冲突的参数组合，例如意图类型被判定为精确事实查询而路径权重却偏向向量语义检索路径。这些冲突参数下发给检索引擎后，各路径召回的内容彼此不匹配，加权融合后的排序结果随之失真。
>
> 因此，即便本领域技术人员出于提高效率的动机将对比文件 3 的多次调用予以合并，所得到的也只是调用次数的减少，其每次调用的任务性质并未改变，输出中依然不存在检索范围、图遍历策略、路径融合权重值这类执行参数，也就不存在维度之间的一致性问题，更不可能获得本申请所述的语义内在一致的技术效果。审查意见以效率为动机推导出本申请的技术方案，与本申请实际解决的技术问题并不对应，属于在已知本申请方案之后的事后分析。

### 4.2 补充二：审查意见的对应关系自相矛盾，且流程顺序相反

这是本轮最有力的一点，代理稿完全没有涉及。建议作为独立的一节插入。

> **审查意见对对比文件 3 的两处对应关系彼此矛盾**
>
> 审查意见在评述权利要求 1 时，对对比文件 3 做了两处对应：
>
> 其一，将对比文件 3 的"多维度上下文信息"对应为本申请的"多维度结构化路由决策数据"。
>
> 其二，将对比文件 3 对初始 SQL 语句的"字段映射校验"对应为本申请的"对多维度结构化路由决策数据中每个字段分别进行单独校验"。
>
> 申请人认为上述两处对应无法同时成立。按照对比文件 3 说明书记载的流程，多维度上下文信息产生于对多源知识库执行检索并按融合规则融合之后（[0045]、[0064] 至 [0065] 段），上下文增强的提示词由多维度上下文信息生成（[0058] 段），初始 SQL 语句由提示词输入大语言模型后生成（[0059] 至 [0060] 段），字段映射校验则是对该初始 SQL 语句进行的（[0061] 段）。可见在对比文件 3 中，被校验的对象是 SQL 语句，而审查意见认定为路由决策数据的对象是多维度上下文信息，两者是该文件流程中前后相隔数个环节的两个不同事物。审查意见从对比文件 3 中分别摘取互不相干的两个步骤，各自对应本申请的一个技术特征，再将其视为一个完整方案，这种对应关系不能成立。
>
> **两者在流程中的位置相反**
>
> 更为关键的是，即使单独考察校验环节，本申请与对比文件 3 的顺序也是相反的。
>
> 本申请的顺序是：大语言模型生成多维度结构化路由决策数据，对该决策数据逐字段校验并对不合格字段回退，再基于校验后的目标决策数据执行多路径检索。校验发生在检索**之前**，其目的是保证接下来的检索能够被正确驱动，如本申请说明书 [0029] 段所记载，经过校验的决策数据作为可靠的检索指令用于驱动底层多种数据源的实际查询操作，从而降低因模型输出异常导致的检索失效风险。
>
> 对比文件 3 的顺序是：先执行检索获取多维度上下文信息，再生成提示词，再生成 SQL 语句，最后对 SQL 语句做字段映射校验。校验发生在检索**之后**，其目的是保证 SQL 语句能够在数据库中正确执行，避免出现表不存在、字段不存在、字段跨表等错误。
>
> 一个在检索之前校验驱动检索的指令，一个在检索之后校验最终产出的查询语句，两者所处环节相反、所要防止的失效形态不同、校验对象不同。对比文件 3 无法公开本申请区别技术特征（2）中的逐字段校验，也无法给出将其应用于路由决策数据生成环节的技术启示。
>
> 此外，两者对校验不通过的处理方式也存在本质差异。对比文件 3 [0063] 段的处理方式是将不匹配信息反馈至大语言模型并补充修正指令、重新生成整条 SQL 语句，属于整体重新生成，且需要再次调用大语言模型。本申请的处理方式是仅对不合格的单个字段执行回退，合格字段予以保留，不再调用大语言模型，如说明书 [0027] 段所记载，该容错机制确保大语言模型在不同异常形态下均能以最小代价恢复有效决策，最大限度保留大语言模型已成功生成的信息。前者是整体重来，后者是局部修补并保留已有成果，技术手段和所要达到的效果均不相同。

### 4.3 补充三：正面回应"执行多路径检索为常规选择"

审查意见对区别技术特征（2）中的多路径检索部分只用了一句话带过。代理稿在区别技术特征（2）的开头把这一步列进去了，正文却没有任何回应。**列而不答，等于默认。**

建议补充以下内容。

> 审查意见针对区别技术特征（2）中的多路径检索部分认为："当通过字段映射校验，获取最终的 SQL 语句之后，执行多路径检索，得到目标检索结果为本领域技术人员的常规选择。"申请人不认可该认定。
>

> 需要一并说明的是，对比文件 3 [0038] 段与 [0045] 段虽然出现了权重数值，但与本申请的检索路径融合权重值有本质区别。

### 4.5 修改一：删除权利要求 1 中残留的"中的至少一个"

本轮修改把多维度结构化路由决策数据一句中的"中的至少一个"删除了，五个维度全部列为必要特征，这一步是对的。但**系统指令信息一句中的"中的至少一个"仍然保留着**，造成权利要求 1 内部前后不一致。

现有表述的问题在于：系统指令信息可以只有一类，而决策数据一句写的是"包括与所述系统指令信息中**各指令**对应的查询意图类型、检索范围、图遍历策略、检索路径融合权重值、时间约束信息"五项全列。若系统指令信息只有一类，则不存在与五个维度一一对应的"各指令"。这一矛盾可能引来专利法第二十六条第四款的问题，也削弱了各维度联合生成、相互交叉参考这一核心论点。

建议将该句改为：

> 基于所述查询文本生成若干系统指令信息，所述系统指令信息包括查询意图类型指令信息、检索范围指令信息、图遍历策略指令信息、检索路径融合权重值指令信息和时间约束指令信息；

即删去结尾的"中的至少一个"。原始权利要求 1 中本有该表述，删除属于范围缩小，不涉及超范围问题。

### 4.6 修改二：必须删除"并行驱动"的表述，说明书中没有这个记载

代理稿在描述区别技术特征（1）时使用了"一次前向传播"的说法。说明书 [0025] 段的原文是"大语言模型单次推理调用是指仅执行一次模型前向传播"，两者一致，可以继续使用。

但代理稿多处使用了"用于**并行**驱动五条异构检索路径"的表述，**这个说法没有依据，必须改掉。**

已对本申请公开文本 CN122388163A 全文做过检索，说明书中"并行""并发"等字样一次都没有出现。说明书对多路径检索执行方式的表述是 [0115] 段的"各路径独立检索并输出带排名的结果列表"，以及权利要求和说明书中的"分别对每个检索路径进行对应的决策检索和排序"。权利要求 1 的表述则是"基于所述目标结构化路由决策数据执行多路径检索"，同样没有限定并行。

保留这个表述有两重风险。一是主张的内容超出权利要求的限定范围，审查员可以直接以未记载于权利要求为由不予考虑；二是说明书中也无此记载，一旦审查员较真，反而会给对方留下攻击口实。

需要注意的是，审查意见中也出现了"在一次调用中并行驱动五条异构检索路径"这句转述，那是审查员在复述申请人上一轮的陈述，源头仍在申请人一方，不能当作审查员的认可。

**建议将意见陈述中所有"并行驱动五条异构检索路径"统一改为"驱动五条异构检索路径"，或改为"分别对五条异构检索路径执行对应的决策检索"。**改动之后论证力度不受影响，本申请的核心主张是决策数据在单次推理中联合生成，不依赖五条路径是否并行执行。
