- **桌面版 SSH 远程连接只走密钥认证，不支持密码**。cuiyang 遇到 CLI 能用密码连远端（`cuiyang@172.24.16.58`）、桌面版连不上的问题。原因是桌面版的 "Add SSH connection" 对话框只有 SSH Host / Port / Identity File 三个字段，没有密码输入框。解决办法是配 SSH 公钥登录：`ssh-keygen` 生成密钥，`ssh-copy-id` 拷公钥，桌面版 Identity File 填私钥路径。桌面版会读 `~/.ssh/config`（内部用 `ssh -G` 解析），可配 Host 别名和 ProxyJump。远端只需 Linux/macOS + sshd，Claude Code 首次连接会自动在远端安装。

- **`ssh-copy-id` 在有多个密钥对时的选择逻辑**。不带 `-i` 时：如果 ssh-agent 在跑且加载了密钥，会把 agent 里所有身份公钥全拷过去；agent 没跑就退回挑 `~/.ssh/id*.pub` 里最近修改的那一个（按时间戳，不是按意图）。都不可控，应显式 `ssh-copy-id -i ~/.ssh/id_ed25519.pub`。连接时也建议在 config 里加 `IdentitiesOnly yes` 只用指定的钥匙，避免挨个试触发服务器 `MaxAuthTries` 拒绝。

- **本体（Ontology）相关的一批核心概念**，为 Reporting 产品的语义层设计打基础：
  - **TBox / RBox / ABox / Axioms / Profile**：TBox 定义有哪些类型；RBox（Relation）定义类型之间能连什么关系；ABox（Assertion）是填好的具体实例事实；Axioms 是必须遵守的约束（违反就报错，例如"每道算掌握度的题必须至少映射一个知识点"）；Profile 是一个具体任务的运行契约，规定它能用哪些概念、要哪些输入、输出什么格式。
  - **CQ（Competency Question，能力问题）**：系统必须能回答的业务问题清单。核心方法论是"CQ 先于本体"——先列要回答的问题，再倒推该建哪些概念和指标，而不是为建模而建模。CQ 同时充当验收标准：本体改完后原来能答的 CQ 不能变成答不出来。
  - **数仓分层**：ODS（原始层，源数据原样存、可追溯可重刷）、DIM（维度层，稳定的实体档案如用户/组织/内容表）、DWD（明细事实层，一条条原子事实）、DWS（汇总层，聚合派生结果如掌握度 0.78）、ADS（应用层，直接喂给报表/页面）。
  - **Pydantic**：Python 里给数据定"模子"、不合规就打回的校验工具。cuiyang 领悟到"用 Pydantic 强约束 LLM 抽取"的价值是把"类型只能从受控词表里选"从事后补救提到抽取源头去管。

## 3. 工作环境 / 公司 / 业务背景

- **CSRS 是 UMU 的知识库/记忆后端服务**（Python，主分支 master，路径 `/Users/cuiyang/projects/umu/csrs`），底层用 PG + Neo4j + Milvus，接 cognee。核心的身份/数据隔离模型（data_isolation_model）：
  - 有两套身份体系。agent 用户和真人用户落到 email 约定区分命名空间：agent 是 `<name>@agent.<tenant>.internal`，真人是 `<name>@user.<tenant>.internal`，同名字符串在两个命名空间下是两个不同的 cognee.User。历史上还有 legacy 格式 `<name>@<tenant>.gateway.internal`。
  - **区分 real user 和 agent 的判定标准是 `csrs_agents` 表的存在性，不是 email 格式**（这是文档明确标注的坑）：一个 cognee.User 若是某条 `csrs_agents` 行的 `owner_cognee_user_id` 就是 agent，否则是真人。分类代码在 `csrs/console/service.py:556` 的 `_owner_label`。按 email 格式分类会把 legacy user 分错。
  - 身份创建入口唯一：`resolve_agent` / `resolve_real_user`（`csrs/identity_resolver.py`）。真人比 agent 多一步：加入 `real_users_role`。
  - Gateway 的四模式归属矩阵（2026-05-06 业务方决策）在 `_resolve_owner_dispatch`：只传 user_name（兼容遗留，废除对象）、只传 agent_name（agent 私有共享 KB，正式设计）、两个都传（真人私有数据，agent 只作过滤标签，正式设计）、都不传（422）。移除兼容后的目标状态是后两种合法传法。

- **Reporting / Prove 是 UMU 的一条产品线，cuiyang 是本体语义层这块的牵头人**。目标是证明学习效果（培训组织得好不好、学员学会没有）。技术栈和 CSRS 不同，用数仓 + Flink。关键业务规则（对任何做度量/评估的系统都适用）：

  - **强弱证据分开**：学习时长这类过程数据只能证明投入，考试和作业才能证明学会。

  - **工程上不推倒重来**：Prove 不重写现有数仓，只在已有链路上加一层语义（补语义 ID 和映射）；本体治理抽成跨产品共享平台，不让每个产品各造一套。存储治理定论：Git/YAML 管发布态 SSOT（每个业务问题一份 YAML：question + answered_by + profile）、Postgres 管治理流程、Graph DB 第一期不上；ABox 不建新物理层，就是 DIM+DWD+DWS 的逻辑整体；第一期不建平台 UI，只用 CI 跑公理校验。
