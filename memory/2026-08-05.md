### 量能三层论：越往下越没用，而且方向相反

这是今天最重要的成果，也是被用户逼出来的。**先给结论表，因为它现在已经写进 `ycui_market_advisor` skill 的 1b4 节，每次调用都要按这个强度引用：**

| 层面 | 实测结论 | 强度 | 怎么用 |
|---|---|---|---|
| **① 大盘量能** | 有量的上涨日后续 5 日 **+0.631%**，缩量上涨日 **−0.120%**（基准 +0.132%）；量水平与次日涨跌 r=+0.103、p=0.0040 | **方向可信但极弱，r² 仅 1.06%** | 可以用来判断「今天的上涨是不是虚涨」，**不能据此下注** |
| **② 板块量能** | 横截面按量比挑板块，放量上涨 +0.396%、缩量上涨 +0.844%（基准 +0.460%）；放量上涨 BH 校正后 **p=0.2668 不显著** | 中等（否定结论较结实） | **不能用「这个板块放量所以更好」挑板块** |
| **③ 个股量能** | 38 只票 × 783 交易日 = 29102 样本，6 组对基准全不显著，横截面 p=0.9876；BH 校正后 **7 个检验一个都没通过** | **强（否定结论最干净）** | **不作个股判断依据**，只报事实不下结论 |

**为什么方向会相反**——这是用户一直觉得别扭的地方，而它不是算错：

- **① 问的是「今天整个市场活跃吗」**，是「天气」问题。全市场成交量放大说明有真实资金在场。
- **② 问的是「同一天里，涨得最凶而且量最大的那个板块，接下来一周会不会最好」**，是「挑哪个」问题。而单个板块放量可能是两件相反的事：资金在建仓（好），或者有人借着热度出货、一日游（坏）。**两种在数据里混在一起互相抵消，所以挑不出优势。**

**这个例子讲通了，值得复用**：一个菜市场。全市场量等于今天总共来了多少人——人多说明市场热，接下来几天生意大概率不错，这个判断是对的。板块量等于在人很多那天哪个摊位前排队最长——排队最长可能是那家真的好，也可能是在搞一元促销、人散了就散了。数据里两种混在一起，所以「排队最长」预测不了下周谁卖得好。而那些人不多但一直在慢慢涨价的摊位反而后续更好，因为支撑它们的是愿意花钱的老客、不是来抢促销的。

**「量能越往下走越没用」这个梯度本身是合理的**：大盘成交量反映的是「整个市场有多少资金在场」，那是一个真实的状态；而单只股票放量，可能是买也可能是卖，两种混在一起就抵消了。

### 同日聚类的最典型陷阱：不按日期配对就会把「市场整体好」误当成「信号好」

这条已经写进 skill 作为必须避开的陷阱。**具体数字**：「当日巨量」组的个股次 5 日是 **+2.591%**，看着远高于基准 **+1.230%**，像是个很强的信号。**但按日期配对（同一天里该组均值减全部均值）之后，差值只剩 +0.032%**——因为巨量的日子本身就集中在市场大涨的时候，而那些天所有票都涨。

**规则：任何跨越多只股票或多个板块的量能统计，都必须按交易日配对。**

### 一个我差点犯的检验设计错误：「显著不为零」不等于「显著不同于基准」

第一版检验测的是「该组次 5 日收益是否显著不为零」，四组 p 值全部小于 0.005，看起来全都显著。**但整个样本的次 5 日均值本来就是 +1.230%（正的），所以任何一组都会「显著不为零」——那个检验在问一个没有信息量的问题。**

### 三篇既有文献的精确算法，以及在 A 股上复刻的结果

用户提出一条方法论要求：**「如果已经有既有的可以套用并验证有效的理论方法存在，你不必自己再去发明一套。」** 我之前那个「近 3 日均量 ÷ 前 3 日均量 > 1.15」的量比是自己拍的，在六个维度上都和文献不一样。

**Lee & Swaminathan (2000)《价格动量与成交量》** —— 成交量口径是**换手率 = 当期成交股数 ÷ 期末流通股数**，不是原始成交量。算法是每月末按过去 J 个月收益分 5 组（R1 输家到 R5 赢家），**独立地**按 J 个月内平均月换手率分 3 组（V1 低 / V2 中 / V3 高），交叉得 15 组等权持有 K 个月。原文在美股（1965-1995）的发现是「高换手率公司具备概念股特征、未来收益更低」「高换手率的赢家反转更快」。

**在 A 股（沪深300 成分股 300 只、36 个月）复刻的结果是方向完全相反**：

| J=6/K=6 | V1 低换手 | V2 中 | V3 高换手 | V1−V3 |
|---|---|---|---|---|
| R1 输家 | +4.71% | +8.94% | +14.21% | −9.51% |
| **R5 赢家** | **+2.12%** | +13.12% | **+16.84%** | **−14.72%** |

低换手减高换手 = **−10.04%**，t=−3.28、**p=0.0010 显著但方向与原文相反**；而且 V1−V3 这一列 5 个收益组**全部为负**（−7.77% 到 −14.72%），方向一致性很强。**A 股是高换手率跑赢，不是跑输。**

**Avramov, Chordia & Goyal (2006)《个股收益中的流动性与自相关》** —— 周频（约 5 个交易日），正好对应用户要的 3-5 天。它明确说明了为什么用换手率的「水平」而不是「变化」：因为 Campbell-Grossman-Wang (1993) 的模型关联的是序列相关模式与换手率的**水平**而非变化。**在沪深300 上复刻，四个检验全部不显著。**

**关键判断：同一批股票、同一个换手率指标，拉到 6 个月就显著（p=0.0010），压到 3-5 天就完全没有。所以问题不在指标，在用户要的这个时间尺度。**

**另外 ACG 原文里有一条对我们特别重要的信息**：文献在大盘股上本来就是矛盾的——「Cooper (1999) 基于大盘 NYSE-AMEX 股票得到了相反的结论……可能是因为 Cooper 用的是最大的那批股票」。**而沪深300 正好就是「最大的那批股票」。**

短线文献的三条主线（都是日频到周频）：Campbell-Grossman-Wang (1993, QJE) 日频，日收益的一阶自相关随成交量上升而下降、高成交量日的价格变动更容易被反转；Conrad-Hameed-Niden (1994, JF) 周频，高交易笔数的股票出现反转、低交易笔数的出现延续；ACG (2006, JF) 周频，周度反转集中在高换手率股票上。

### CSRS 记忆模块（CE）的写入与读取是两套逻辑

用户问「外部调用 `afterTurn()` 把对话消息传给 CSRS 后，CSRS 如何区分 knowledge 和 memory 这两个 scope」。

**答案是写入的时候不区分**。`after_turn`（`csrs/ce/engine.py:471`）拿到对话消息后，**同一批消息被两条并行的抽取链各跑一遍**，分别写进「记忆」存储和「知识」存储——一句话可以同时变成一条 memory 记录和几个知识图谱节点，不是二选一。

- **Branch A（记忆）**：`MemoryExtractor.extract()` 让大模型从对话里挑「值得记住的关于用户的信息」，分五类（事实、偏好、关系、事件、技能）。有一条硬约束：**只从 user 说的话里抽**，assistant 的回复只当上下文，除非用户明确采纳了建议。抽出的候选先去 Milvus 找相似老记忆，再让大模型判 ADD / UPDATE / DELETE / NO_CHANGE，最后写 PG `memory_records` 加 Milvus `csrs_memories`。
- **Branch B（知识）**：同一批消息走三个抽取器——`_step2_graph` 抽实体关系写 Neo4j 加 Milvus、`_step3_es` 把对话文本做全文索引写 ES、`_step4_temporal` 抽时间事件节点（**这一个线上是关着的**）。三个开关代码默认都是 false、靠 env 打开，线上前两个是 true。

**真正区分两个 scope 的地方在读取**（`POST /ce/assemble`）：用一次大模型对**用户当前这句 query** 分类，输出 `scope` 取值 knowledge / memory / 两者都要 / trivial（无检索意图），再据此决定走哪条召回链。

**一个必须纠正的前提**：「写入按哪个 scope」这个问法在代码里不成立——**scope 不是数据上贴的标签，而是「数据存在哪个库」的代称**。库里没有 `scope` 字段，assemble 也从不按 `scope == "memory"` 过滤数据；它是拿 scope 决定调哪个 retriever，而每个 retriever 只读固定的那几个库。

**knowledge scope 的数据有两个来源**，而且写进的是**同一个 ES 索引**：文档上传的 cognify pipeline（主来源，走完整链路：切块、citation、表格、图片多个 task），以及对话抽取（补充，只做抽实体关系和索引对话原文两件事）。对话侧在 metadata 里打 `source: "conversation"` 做区分。Neo4j 那边也一样，对话抽出的实体和文档抽出的实体是同一张图上的节点。**所以 knowledge 路查询时不区分 chunk 来自文档还是对话，两者在融合排序里平等竞争。**

**为什么对话要写两遍**——不是冗余备份，两条链产出的形态和用途不同：Branch A 产出的是**关于用户的陈述句**，一条条独立、可更新、带活跃度衰减，用户说「我改主意了」会触发 UPDATE 或 DELETE；Branch B 产出的是**实体关系图加对话原文全文索引**，不会因为改主意就删节点，服务的是「关于某个实体我们知道哪些事」这类跨来源、可多跳推理的查询。

### 数据仓库里「衍生指标」这个类别（umu/prove）

`total_points_rank`（积分排行榜用的那一列）**是五项分之和**，五项的名字在产品代码 `module/logic/coursestat/ConstSet.php:35` 写着：基本分、全达标分、优秀分、积极分、特别表彰分。而**这五列就在同一张 `group_done_count` 表上**（证据是 `GroupDoneCount.php:700` 一条字面 SQL 直接 select 了六列），**我们的镜像只拉了三列**。

所以它是标准的**衍生指标**（OneData 体系的说法：五个原子指标相加），而五个原子指标就在同一张表里。在线核实（课程 640312，3062 名有积分学员）总分精确等于五项之和。

**这个例子讲通了**：就像月薪条上只印了「实发 12000」，而基本工资、绩效、加班费、补贴、扣款五项都在同一张表里、财务系统也存着，我们抄的时候只抄了那一个总数。于是老板问「谁的绩效最高」答不了——不是数据没有，是我们抄的时候把它扔了。而且从 12000 倒推不出它是「10000 基本 + 2000 绩效」还是「11000 基本 + 1000 绩效」。

### umu/prove：分类体系对齐 + 衍生指标拆分

**walkthrough 重录已提交**（`ac69cbc`），三个例子对应被删那条视图的三种用法，顶部有替代关系对照表。

**回答了用户两个质疑**：

- **`dimensions` 那个是命名错位、不是语义错误**。这个键一个兼两职：有 `measures` 时它是 GROUP BY 键，没有时是纯投影（`compiler.py:627` 的条件），实测生成的 SQL 没有 GROUP BY。但用户指出的问题成立——`total_score` 是数值事实、`submit_count` 是序号，叫「维度」在语义上是错的。**而且这个错位加重了那份 spec 要治的混淆**：判据用「维度全是透传的物理列」当数据集的信号，而这个信号能成立恰恰因为 `dimensions` 被当成了「任意投影列」。
- **`total_points_rank` 是衍生指标**（见第 1 节）。这和 `one_shot_full` **形态相同、成因不同**：那个复合是我们发明的，这个是产品发明的，但分量同样在数据里。

**补了 spec 的 §1.4**：两套业内体系都证实「数据集不是指标」，但它对应的**不是新造一类，而是 `semantic_model`**——而我们的 `mapping-registry` 已经很接近了。所以那份 spec 自造的 `kind` 四值可能是多余的，把两条路的代价对比写进去、列为未决。另外记了两个能力缺口：**cumulative**（累计到某天有多少人完成）和 **conversion**（看了微课之后又通过考试的有多少），两类都没有。

**三项等用户批准的事**：① 镜像补拉五项分并登记成度量（定义来自物理列自己的取值，不是任何问法的产物；总和推不出分量；不加则「谁最积极」「有多少人拿到优秀分」答不了）；② 把 `dimensions` 拆成 `columns`（投影）与 `group_by`（分组），让「数值事实不能登成维度」在语法层成立而不是靠人记住，代价是改编译器加动约 24 条声明；③ `grain_kind`（26 行枚举加一条判据加一句路由提示），业内两条路都要它，可以先做。

### 用户今天做的纠正（三次质疑，每次都指出了实质缺陷）

**第一次：「改 #1 我觉得有风险。因为我一直听说的也是，某个板块有明显的量了，才说明这个板块开始走稳了。再比如说，一般 A 股市场当天的成交量不够，那么就不能说是向上趋势。你查一下相关的理论研究。」**

| 用户的说法 | 我当时测了吗 | 性质 |
|---|---|---|
| 某个板块有明显的量，说明板块走稳 | 测了一部分（横截面挑板块） | 挑标的 |
| **A 股当天成交量不够，就不能说是向上趋势** | **完全没测** | **判断市场状态** |

**第二件是「时间序列上的状态过滤」，和「横截面上挑哪个」是不同的问题。用我上一轮的结果去否定它，是我的错。** 补测之后，全市场层面的结论支持用户的说法（有量上涨日后续 5 日 +0.631% 对缩量上涨日 −0.120%）。

**教训：把某个范围内测出的结论说成普遍命题，是最容易犯又最难自己发现的错。** 我测的是「同一天里按板块量比挑标的」，却把结论说成「放量不能判断后续上涨空间」。

**第二次：「我对你说的缩放量对个股走势的影响的结论标识怀疑。比如你对放量的定义是否合理，是否能够检测出这种影响？你去搜索一下业内的研究，这些研究一定是有数据的。」** 并给了两条具体要求：看这些研究的结论和支持数据是什么、用它们的公式和计算方式到 A 股上算。

**我能指出自己的三个具体缺陷**：量比的定义是我拍的（近 3 日÷前 3 日）、窗口只有 5 天、样本只有 38 只高度同涨同跌的科技股。查了原文之后发现**我的做法和文献在每一个维度上都不同**。

**第三次：「我的想法是，如果已经有既有的可以套用并验证有效的理论方法存在，你不必自己再去发明一套。」** 这是一条持久的方法论要求——**优先复刻有验证的既有方法，不要自造指标。**

### 我今天犯的错

**把范围有限的测试结论说成普遍命题**（见上）。这是今天最主要的一次。

**检验设计错了一次**：测「该组是否显著不为零」而不是「是否显著不同于基准」，四组 p 全部 <0.005 看着都显著。**如果不发现，我会告诉用户「个股放量上涨显著有效」，正好反了。**

### 今天有效的做法

**被质疑时先去查文献原文、按原文精确算法复刻，而不是辩护自己的版本。** 三篇文献的精确设定（换手率定义、分组方式、时间尺度、为什么用水平而不是变化）都从原文取，而不是凭印象。

**给每张表配「这张表在回答什么」加「读法」。** 这是昨天写进 CLAUDE.md 的规则，今天全程执行，用户的理解成本明显下降。

**用生活化例子讲统计概念。** 菜市场那个例子把「为什么两层的方向相反」讲通了；月薪条那个例子把「衍生指标只登总和是有损的」讲通了。

**主动给「当前有效结论清单」台账。** 这一轮反复修正，中途主动列了哪些成立、哪些已撤回、哪些还没验证——这是昨天写进 CLAUDE.md 的第一条规则，今天证明有用，因为用户是跳着看的。

**把「否定结论」也当成成果如实交付。** 「买最强板块」六个检验全灭、个股量能七个检验全灭、短线换手率四个检验全灭——这些都写清了，而不是继续找一个能通过的组合。**同时给出强度分级**（大盘弱有效、板块中等否定、个股强否定），让用户知道该多信哪一条。
