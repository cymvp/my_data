### 企业 SQL 基准的两条细节（昨天只记了总数，今天补全）

昨天记了「直接问 SQL 16.7%、问知识图谱 54.2%」。今天补出两条更有用的：

**第一，有一条可操作的经验线：一道题要连 5 张以上的表，SQL 路线准确率就掉到零。** 不是低，是零。

**第二，两条路线错的方式完全不同**，这一条比总准确率更有指导性：

| 路线 | 怎么错的 |
|---|---|
| 直接问 SQL | **编**——编不存在的列名、编库里没有的取值当筛选条件、编看着合理其实不对的表连接 |
| 走知识图谱 | **走错路**——起点终点都对，中间的属性路径接错，或者关系方向搞反 |

**这两条各命中 prove 的一处设计**：前者对应「LLM 不写 SQL、不产生数字」那条纪律（从结构上把三种编造堵死了）；**后者是个警告——`rbox.yaml` 里的关系定义越绕、跳数越多，出错概率越大。**

### LOT 的三条（昨天被 digest 截断，今天补齐）

**第一，需求不必全写成能力问题（CQ）。** 作者二十多年经验的观察是：**有些知识天生是陈述句，硬掰成问句很别扭**——他举的例子是「一个传感器观测某个属性」被迫写成「什么被传感器观测？」。

**我们的 CQ 注册表现在是唯一形态，这个毛病正在发生**：比如「一个考试属于一个小节」这种结构性知识，写成「一个考试属于哪个小节？」——**这个问句没人会真的问，它只是为了塞进 CQ 格式而存在。** LOT 给的三选一是能力问题、自然语言陈述、表格；**表格那一种对我们最值，因为我们本来就有结构化的物理表清单。**

| | 做法 | 实践中 |

| **软复用** | **只引用对方元素的标识符** | **多**，作者引的实证说这才是常态 |

### OntoEKG：精确匹配与模糊匹配的巨大落差

同一份产出，两种评分算法：

| 领域 | 精确匹配 | 模糊匹配 |
|---|---|---|
| 数据 | 0.102 | 0.724 |
| **金融** | **0.000** | 0.121 |
| 物流 | 0.048 | 0.431 |

**意思对得上，词一个都对不上。而本体恰恰是词对不上就没用——判重靠的就是词一致。**

**金融那个 0.000 的原因值得单记**：不是模型笨，是**「哪些词该进本体、哪些属于范围之外」这个判断分歧太大**。

**这一条正好是「新增字段、新增词表条目必须先问业务方」那条纪律的外部佐证**——理由本来是「这个口径业务上是否真的存在，只有懂业务的人能拍板」，**现在有一篇论文用 0.000 证明了同一件事**。

### LOM 那篇的两样可直接用的东西

**第一，隐含外键的四因子函数，可以抄来查漏**：列名语义相似、类型兼容、取值重叠、基数模式——**每一个都可算，不需要模型判断**。

我们现在的关系全是人工登记在 `rbox.yaml` 里的，**没有任何机制去发现「这两列其实该连但没人登记」**。拿这四个因子做一次性扫描**查漏**（不是自动建关系），是可行的。

**第二，那张消融表里的 18.95%**：

| 拿掉什么 | 准确率 |
|---|---|
| 完整模型 | 89.47% |
| 拿掉思维链 | 78.42% |
| 再拿掉指令微调 | 61.66% |
| **再拿掉图编码器** | **18.95%** |

原话是：**缺少专门结构嵌入与任务适配的标准大模型，从根本上不具备做图推理的条件。**

**这对我们是个量化的理由**：凡是要求模型「沿着本体结构走对」的地方，都不该指望通用模型做对；**把这类判断编译成确定性规则，方向是对的**。

### 一致不等于融贯（今天精读第一篇，OM-2026）

对齐三个国防上层本体（英国 IES、英国 HQDM、美国北约的 BFO）。**中心论点：大家跑的那个验收检查是错的判据。**

三层判据必须分清：**一致**（有模型，跑得通）／**融贯**（没有命名类不可满足，每个类都还活着）／**保守**（合并没有替某个输入本体多说它自己没说过的话）。作者原话：**「一个一致的本体，完全可以被一个『其中一百个类干脆是空的』的模型所满足。」**

两个硬发现：

- **GCHQ 发布的 `hqdm.owl` 本身就不融贯**——229 个命名类里 **39 个在加任何对齐之前就不可满足**，而这个缺陷**在断言层级里看不见、一致性检查也查不出来**。后果是任何映射到这 39 个之一的对应关系**目标可证为空**；基于这种参考报精确率召回率，**报的是「在空集上达成一致」**。
- 13 条专家映射朴素提升成等价后：**一致性检查通过**，同时**新增 100 个不可满足类 + 218 条保守性违反**，死掉的 100 个全是 IES 的业务类（`ies:Accused`、`ies:Arrested`、`ies:Witness`、`ies:AtWar`）。**而这一百个类是被一条边害的**——十个类目标里恰好一个落在那 39 个原生伤亡里，只弱化那一条边，新增不可满足数就从 100 掉到 0。

**修复办法叫方向搜索**：不删映射，而是**把每条对应关系的方向（≡ / ⊑ / ⊒ / 丢弃）当作搜索变量**——因为 SKOS 不携带逻辑承诺，它压根没告诉你强度是多少，**而强度恰恰是该被搜的东西**。每条被拒绝的方向都**带着推理机给出的反例返回**。用 HermiT，约 35 次调用，笔记本上两分钟，完全确定性。

**假朋友试金石**：`ies:Event`（有持续时间、有参与者）vs `hqdm:event`（瞬时边界、无持续时间无参与者），**标签一样含义相反**。LogMap、LogMapLt、Qwen3-Coder-30B 及其 IES 专门微调版**全部掉进去**，只有推理机裁判的搜索避开了。作者判断：**「大模型裁判恰恰在词法基线也能答对的地方准确，恰恰在两个标准真正分歧的地方失败——而后者才是价值所在。」**

### 让大模型装成差生，它装不像（今天精读第二篇）

379 道 SAT 代数题、5 个掌握度画像、三个厂商三个模型（Gemini 3.1 Flash Lite、Claude Haiku 4.5、GPT-5.4-mini）：**无论画像是什么，准确率全在 96.8–100%**，包括提示词里明写「大多数代数概念掌握度都很低的吃力学生」那个画像。

**更狠的一张表**：把题按知识链切成早期/混合/后期，看「早期弱」「后期弱」两个画像会不会各自该弱的地方弱——**直接提示法在六个格子里全部 100.0%**。**它不是把差生装得不够差，是压根没有「差在哪」这个维度。**

做法是**把「对错」从大模型手里拿走**：从教材抽课程知识图谱（864 条三元组），把每题解法分解成**所需三元组的链**，给每条赋掌握概率，**采样先定对错**，大模型只负责把已定结果讲成第一人称说理。准确率降到 44.1–85.2%，出现单调梯度（85.2% > 57.8% > 44.1%）。

**四段消融里增益最大的是「分类法加权」（+14.0 到 +19.5pp）**——漏掉一条纯定义性事实不该和漏掉一条程序性/关系性的一样重。这用的正是**布鲁姆的知识维度四类**，而**我们把它当分类标签，人家当权重**。

另有一个正交维度我们没有：**「检索 vs 执行」二分**——一条知识**取不出来**和**取出来但用错**是两种失败，对应不同的教学干预。

### 「验收标准选错了」这个形状，四天里出现了三次

- **8/29 LLMs4OL**：总体语义图相似度 0.8692 很好看，**但非分类关系抽取 F1 是 0.0000**——总体指标掩盖了某一类彻底为零。
- **8/29 SymbolLKG**：`Generic` 兜底类别吞掉路由信号——落进「其他」的东西丧失了后续所有基于类型的处理能力。
- **8/30 一致不等于融贯**：一致性检查通过，同时 100 个业务类死掉——**跑得通不等于每个类还活着**。
- **8/30 让大模型装成差生**：准确率平坦在 96.8–100%，**六个格子全是 100.0%**——总体准确率掩盖了「完全没有技能维度」。

**共同形状：一个总体指标通过了，而某个结构性的维度整个塌了，且在总指标上不可见。**

**可搬到受控词表的三层判据**：
- **一致** ≈ 改完之后系统还能跑起来（我们现在实际在用的）
- **融贯** ≈ **一个取值域收窄之后，有没有哪个原本合法的组合变成永远无法出现**（没查过）
- **保守** ≈ **加一条词表条目，会不会让两条本来不判重的记录变成判重**（也没查过）

而 HermiT 那个成本（35 次调用、两分钟、确定性）**低到没有理由不做**。

### 用来验证一个机制的证据，不能是那个机制自己产生的

SSKG 那篇的做法值得抄：arm-d **按构造**会给每个错误答案打 `first_failed_triple_id`，**但他们没拿这套标注去自证「我们能诊断」**（那是循环论证），而是改用**独立于该机制的经验相关性**——三元组掌握度与错误率的 Spearman ρ = −0.459（p≈10⁻²⁸）。

**我们做判重、做消解时，也很容易用「我们自己打的标签」去证明「我们标得对」。**

### 合取链的长度惩罚：粒度越细，达标概率越低

SSKG 那篇的 P5 画像最弱的格子是「混合」而不是「后期」，作者的解释是：**混合链平均更长，在合取规则下每多一步就多乘一个存活概率**，所以混合题迫使 P5 经过它薄弱的步骤**外加一个长度惩罚**。

**对我们的含义**：如果把一个能力拆成多个细粒度条目再要求全部满足，**条目越细，达标概率越低——这不是学员变差了，是我们的建模粒度在制造难度**。

### 「知道要建什么了，就别再遍历文献」

LOT 明确劝阻「从需求出发穷举找现成本体」，理由是研究、理解、比较那么多模型非常费时；正确顺序是**先做出初步概念化，稳定之后再去找**。

我们这几周是反着来的，**但判断是没错**——因为当时连画像该有哪些字段都没定，**读文献本身就是在做概念化**。**这条的适用边界很清楚：前提是「你已经知道要建什么」。**
