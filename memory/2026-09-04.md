## 1. 今天获得的知识与技能

### `rdfs:domain` 是推理规则不是约束——这是今天最重要的一条，而且我先说错了

**我写过一条错的公理**：为了表达「课程有标题」，我顺手写成 `∀x∀v. title(x,v) → Course(x)`（凡是有标题的都是课程）。**崔扬指出它落不了地，我撤回了。**

**错在哪，有仓库里的实证**：`title` 这个字段名在 `mapping-registry.yaml` 里挂在**四个实体**下——`course_dim`（第 348 行）、`session_dim`（331、341 行）、`participation`（77 行）、`session_completion`（176 行）。按那条公理，**一个小节有标题就会被推成课程**。而选型文档 4.4 节自己已经把 `rdfs:domain` 列为陷阱，我在 3.3 又用了它，前后矛盾。

**W3C 规范对 `rdfs:domain` 只规定了一句话**（推理规则编号 rdfs2）：

```
对任意 x 和 y，如果  x P y  成立，并且  P rdfs:domain C  成立，
那么                x rdf:type C  也成立。
```

**整份规范里没有第二句关于它的规定**，它的全部含义就是这一条蕴含式。具体形态：

```
已有：  title  rdfs:domain  Course        （声明）
已有：  s_901  title  "第一节 合规基础"     （数据：一条正常的小节数据）
自动加：s_901  rdf:type  Course            （RDFS 自己加进库里，不问任何人）
```

**「定义域」这个词借自数学，但没借那道闸门。** 数学里说函数 f 的定义域是 A，人脑子里装的是一道闸门：A 以外的东西送进去是错误。RDFS 借了词，没借闸门——**因为 RDFS 里根本没有「违规」这个概念**：它采用开放世界假设，推理是单调的，加进来的任何一句话只会导出更多结论，不会把已有数据判成非法。**一个只能往前加、不能拒绝的系统，拿到「P 和 C 有关」这个信息时，唯一能做的事就是补一条 `x rdf:type C`。**

崔扬追问了一个很锐的点：「『只有 C 的成员才允许用 P』和『凡是用了 P 的东西就是 C 的成员』有什么区别？」

**答案**：前者里的「允许」预设了一个把门的——有人有权说不行，并且有一条报错的通路。后者没有这个词，它只是陈述一个事实。**RDFS 两样都没有**，所以 `rdfs:domain` 只能是推理读法。要约束读法，就要换一个本身带违规通路的系统，那就是 SHACL。

**写这行声明的人心里想的通常是「报违规」，RDFS 执行的是「补结论」。**

### 属性的正确表达方式：全局命名 + 类侧公理

**属性是一个全局的二元谓词，它自己不绑定任何类。** 哪些类的个体带这个属性，由每个类各写一条自己的公理，**方向和错的那条相反**：

```
Course  ⊑ ∃title.文字        每门课程都有一个标题，标题是文字
Session ⊑ ∃title.文字        每个小节也有一个标题
Course  ⊑ ≤1 title           每门课最多一个标题（可选）
```

一阶写法 `∀x. Course(x) → ∃v. title(x, v) ∧ 文字(v)`。**`Course` 在谓词位，参数位上是变量**，和「类不进参数位」一致。加一个新类要用标题，就为那个类再写一条，`title` 本身不动。

**唯一可以全局声明的是值域**：`⊤ ⊑ ∀title.文字`（标题的值永远是文字）。这条对所有共用它的类都成立。**定义域不放全局。**

**生活对照**：报销单和请假单都有「提交日期」这一栏。正确说法是「每张报销单都有提交日期」「每张请假单都有提交日期」，两条规则各写在各自的表单模板上。**错误说法是「凡是有提交日期的单子都是报销单」**，一写出来请假单就全变成报销单了。

### 定义域的严格定义（崔扬要求措辞严谨后补的）

崔扬指出「在属性上写定义域」这句话不严谨。**严格定义**：

一个二元谓词 `R` 的解释是一个有序对的集合。

```
dom(R) = { x | ∃v. R(x, v) }      定义域 = 所有出现过的第一分量
ran(R) = { v | ∃x. R(x, v) }      值域   = 所有出现过的第二分量
```

**定义域由数据决定，不由人声明。** `title` 的定义域就是「实际带着标题的所有个体」——课程、小节、直播场次都有标题，它的定义域就是这三类个体的并集。

**`rdfs:domain` 和 `∃R.⊤ ⊑ C` 声明的不是定义域本身，而是一条关于定义域的公理。** 这句话可真可假，**不能当规定用**——这是今天最凝练的一条。

### 三种句子的形式区别：`⊤`、`∃R.C`、`∀R.C`

崔扬问「`∃containsSession.⊤ ⊑ Course, ⊤ ⊑ ∀containsSession.Session` 每个符号是什么，我全看不懂」。符号表：

| 符号 | 读法 | 含义 | 生活对照 |
|---|---|---|---|
| `⊤` | 顶 | 所有个体组成的类，任何东西都属于它 | 所有单据 |
| `C ⊑ D` | C 包含于 D | C 的每个成员都是 D 的成员 | 报销单都是单据 |
| `∃R.C` | 存在 R 到 C | 沿 R 至少能连到一个 C 类个体的那些个体 | 至少钉着一张发票的单据 |
| `∃R.⊤` | 存在 R 到任何东西 | 沿 R 至少连到一个个体的那些个体，不管连到谁 | 后面钉着东西的单据 |
| `∀R.C` | 凡 R 皆到 C | 沿 R 连到的每一个都属于 C 的那些个体。**一条 R 边都没有的个体也算在内**，因为「连到的每一个」没有反例 | 钉着的东西全是发票的单据，**包括什么都没钉的** |

两条公理的意思：
- `∃containsSession.⊤ ⊑ Course` = `∀x. (∃y. containsSession(x,y)) → Course(x)` —— 约束关系的**主语**端，`rbox.yaml` 里叫 `domain: Course`
- `⊤ ⊑ ∀containsSession.Session` = `∀x∀y. containsSession(x,y) → Session(y)` —— 约束**宾语**端，即 `range: Session`

**这两条和 `Course ⊑ ∃containsSession.Session` 方向相反**：后者说「每门课至少有一个小节」，前两条说「用了这条关系的两端必须是什么类」，**不要求每门课都有小节**。

### 为什么 `rbox.yaml` 写 `domain: Course` 是允许的（B2 不禁这个）

崔扬问了这个看似矛盾的点，答案值得记：

**B2 禁的是共用名字带定义域。** `title` 同时用在课程和小节上，在 `title` 上写「定义域是课程」就只能写一个类，写了就把小节排除，再让推理机按它推，有标题的小节就被推成课程。

**`containsSession` 的情形不同**：这条关系只在**一对类**之间用，主语永远是课程、宾语永远是小节，**没有第二对类来共用它**。名字不共用，B2 担心的两个后果都不会发生。

**导出时的区别才是关键**：同样一句 `domain: Course`，导成 `rdfs:domain` 就成了推理规则（主语不是课程时把它改判成课程，不报错，违反 B5）；**导成 SHACL 形状就成了检查**（目标是「所有作为 `containsSession` 主语出现的节点」，要求它们是 `Course`，不是就报违规）。**导出脚本只生成后者。**

### RDF / RDFS / SHACL 三者的定位（今天用了两个 session 才讲清）

**RDF 只有一种数据单位：三元组。** 但要注意崔扬指出的一个自我矛盾——我先说「RDF 没有主谓宾的语义，它只知道是一个三元组」，后来又说「三段分别叫主语、谓词、宾语」。两句都对但需要区分：**名字叫主谓宾，但 RDF 本身不规定这三段该怎么解释**。

**RDFS 是配套的一小套词汇** + 十几条推理规则。**它自己不做校验。** 名字里的 Schema 和数据库里的 schema 是两回事：**数据库的 schema 不符合就拒绝写入，RDFS 不符合就推出新事实让它符合。**

**RDFS 里类和属性的区分**（崔扬追问出来的结论）：**除了内置词会规定主语/宾语该填类还是属性，RDFS 在语法和规则上并不区分类和属性。** 类装的是东西，属性装的是**成对**的东西——一个类是一群个体组成的集合，一个属性是一堆有序对组成的集合。**判据：光凭一个东西能不能判断它在不在里面。类可以，属性不行。**

**SHACL 是 W3C 2017 标准，基本单位叫「形状」，一张形状就是一张检查单。** 崔扬说我第一版解释「极其混乱」（什么是节点、什么是字段、为什么适用于 Course 节点但检查的是 containsSession 字段），我重讲了：

**RDF 图里只有节点和边，没有「字段」这个东西**（我撤回了那个说法）。检查单的两步机制：
1. `sh:targetClass Course` —— **站在**所有有一条 `a` 边指向 `Course` 的节点上
2. `sh:property [ sh:path containsSession ... ]` —— **看**从那个节点出发的、标着 `containsSession` 的边

**「适用于课程节点，检查的却是 containsSession 边」不矛盾**：适用于谁决定站在哪个节点，检查什么决定看哪种边。**检查单永远站在一个节点上往外看。**

报销对照：一张报销单是一个节点，右上角印着「报销单」是它的 `a` 边，背面钉着的每张发票是另一个节点，「钉」是一根标着「附件」的边。财务先拿起每张印着「报销单」的单子（站在节点上），再翻到背面只看标着「附件」的东西（看那种边）。

### SHACL 形状本身也是三元组

崔扬问「`sh:closed true` 并不是三元组啊？」——**它是。** Turtle 的 `;` 意思是「下一条三元组主语相同，省略主语」，拆开就是：

| 主语 | 谓语 | 宾语 |
|---|---|---|
| `umu:ClassNodeShape` | `rdf:type` | `sh:NodeShape` |
| `umu:ClassNodeShape` | `sh:targetClass` | `rdfs:Class` |
| `umu:ClassNodeShape` | `sh:closed` | `true`（`xsd:boolean` 字面量） |
| `umu:ClassNodeShape` | `sh:ignoredProperties` | 一个列表节点 |

**`( a b c )` 是列表的缩写**，展开后是一串空白节点，每个节点两条边：`rdf:first` 指向当前元素、`rdf:rest` 指向下一个，最后一个的 `rdf:rest` 指向 `rdf:nil`。**两个元素展开是五条三元组，八个元素是十七条。** 校验器读到 `sh:ignoredProperties` 时沿 `rdf:rest` 走到 `rdf:nil`，收集所有 `rdf:first` 得到白名单。

**`sh:targetClass rdfs:Class` 的意思**：站在所有有 `a rdfs:Class` 边的节点上，也就是 `prv:Course`、`up:Fact` 这些**类节点本身**，不是课程 752468 这种个体。RDFS 把 `rdfs:Class` 定义成「所有类组成的类」，它自己也是自己的成员（规范写着 `rdfs:Class rdf:type rdfs:Class`）。**这是 RDFS 内置的元类，基石 B1 管的是业务类不能进业务参数位，签名这条边不在禁止范围内。**

### 公理和三元组不是二选一

崔扬问「什么时候需要定义公理，什么时候定义三元组？我糊涂了」。**这是一个维度混淆**：

| 维度 | 取值 | 判据 |
|---|---|---|
| **说什么** | 公理、断言、注解 | **看句子里有没有具名个体** |
| **怎么存** | 三元组（RDF）、YAML 条目（本仓）、数据库行（数仓） | 看它落在哪个系统 |

**在 RDF 里，公理、断言、注解全部都用三元组存。** 你真正要分的是「这句话是类层的规则（公理），还是个体层的事实（断言）」。

生活对照：报销制度写着「每张报销单必须有一位审批人」是公理，写在制度文件里；「张三 3 月 5 日那张单的审批人是李四」是断言，写在单子上；「本制度简称报销制度」是注解。**三句话如果都录进同一个系统、每句存成一行主谓宾，那就是三元组。制度文件不会因为存成了同样的行格式就变成一张单子。**

| 注解 | 34 个类**全部**有 `display_name` 和 `description`，4 个有 `surface_forms`；45 条关系有 `description` | `tbox.yaml`、`rbox.yaml` |

### 值、取值域、类三种写法的选择（崔扬问「标题也可以是类吗」）

**「标题有各种取值」不会让标题变成类，每个属性都有很多取值。** 判据是**要不要谈论某一个标题本身**：

| 情形 | 判据 | 建法 | 公式 |
|---|---|---|---|
| 标题只是一串文字，取值任意 | 值说不出成员，值上不挂属性 | **属性**，值域是数据类型 | `∀x. 课程(x) → ∃v. 标题(x,v) ∧ 文字(v)` |
| 取值是固定小清单（难度只有初/中/高级） | 值能点名、数量有限、**别的规则要按名字引用它** | **取值域**：清单是类，每个值是个体，课程到值是**关系** | `难度等级 ≡ {初级,中级,高级}` |
| 要谈论标题本身（哪种语言、谁写的、多少字） | **值上要挂属性**，值有自己的身份 | **类**：每个标题是个体，标题文字变成它的属性 | `∀x. 课程(x) → ∃t. 有标题(x,t) ∧ 标题(t)` |

**区别的关键**：难度的取值是三个**能点名**的东西，规则会引用它们（「初级课程不计入考核」）；标题的取值是任意文字，**没有规则会说「标题为『新员工合规』的课程如何如何」**。

**第三种写法就是物化**：把一个原本是值的东西升格成个体，原来的文字降成它的一个属性。**学员画像的事实行就是这样来的**——一条陈述有七个成分，二元关系装不下，于是陈述本身成为个体。

### CSRS 的文档格式支持：`.docx` 支持，`.doc` 不支持

**准入白名单只有一处**，`csrs/gateway/router.py:55`：

### bash 的一个 UTF-8 变量边界 bug

**`$VAR` 后面紧跟全角 `）`（UTF-8 三字节 `ef bc 89`）时，bash 把首字节当成变量名的一部分吞掉。**

```
zsh  裸写 $TK） → 已启动（Tk 8.6），PID 1   ✅
bash 裸写 $TK） → 已启动（Tk ??，PID 1      ❌
bash ${TK}）    → 已启动（Tk 8.6），PID 1   ✅
```

**修法是加花括号定界 `${VAR}`。中文标点后面跟变量的场景都该这么写。**

### 描述语言选型的最终形态

**推荐乙：RDFS + SHACL，加在现有 YAML 之上而不是替换。**

- **正本仍是 YAML**，RDFS 和 SHACL 是导出后的标准格式
- **RDFS 只负责签名和注解**（`rdfs:Class`、`rdf:type`、`rdfs:subClassOf`、`rdf:Property`、`rdfs:label`、`rdfs:comment`）
- **约束全部交给 SHACL**，`rdfs:domain` / `rdfs:range` **禁用**
- **公理在乙方案里的身份是「检查单」不是「推理前提」**，这个选择在 B5 定下，SHACL 是它的书写形式

**对照数据库**（这个类比崔扬认了）：`CREATE TABLE course (id INT PRIMARY KEY, title VARCHAR NOT NULL, ...)` 既是表结构定义也是两条校验规则，**没人会说 DDL 是校验规则不是模型**。`sh:targetClass prv:Course` 对应 `CREATE TABLE course`，`sh:maxCount 1` 对应唯一约束。**区别只有一点：数据库把定义和数据装在同一个引擎里、写入时就拦；乙方案把形状图和数据图分开、校验器按需跑**（B6）。

## 4. 经验与教训

### 「定义域是数据决定的集合，人能写的只是关于它的一句话，这句话可真可假，不能当规定用」

**这是今天最凝练的一条，也是那个错误公理的根因。**

我把「课程有标题」顺手写成「有标题的都是课程」，是因为脑子里装的是数学/编程里那道闸门。**但 `dom(R) = { x | ∃v. R(x,v) }` 是由数据决定的，声明改不了它，只能加一条关于它的公理，而那条公理在共用属性的场景下是假的。**

**固化成检查动作**：写下任何一条「凡是……都是……」之前，先问「这句话在我的数据里有反例吗」。有反例就是假公理。**找反例的方法是去注册表里数这个名字被几个地方用了。**

### 「声明存在不等于能力可达」

CSRS 的 loader 层声明支持 `.doc`（`document_loader.py:73` 的 `supported_extensions` 里有它，MIME 列表里也有 `application/msword`），**但 `.doc` 在网关白名单就被挡下了，走不到 loader**。

**grep 到 `doc` 就以为支持会判反。** 这和 CLAUDE.md 里那条「回答某个东西有没有被使用必须解析结构」是同一个形状，**但更进一步：即使找到了真正的声明位置，还要问「这个声明所在的层，请求到得了吗」。**

**判断方法是从入口往下追一遍**，看有没有更靠前的闸门先把它拦掉。

### 「不是不支持，是抽出来了但挂不上」——这个区分决定改动性质

崔扬问「docx 不识别图片能不能支持、改动多大」。**如果我直接答「不支持，要新做一条管线」，估的工作量会差一个量级。**

实际情况是：抽图管线格式无关、docx 抽图一张不丢（我补了实测证明），**断点只在一个取 `prov[0].page_no` 的地方**。

**固化**：被问「X 支不支持、要多大改动」时，**先验证 X 到底是「完全没有」还是「有但某一环断了」**。这两者的改动量和风险完全不同，而且答案往往是后者。**验证方式是拿真实输入跑一遍最底层的那个服务**，不要只读代码。

### spec 里写着「本期只测了 A」的地方，就是该去补测的地方

CSRS 的图片 spec 第 261 行原话：「抽图管道格式无关……但本期实测与调优**仅覆盖 PDF**……未测前按 PDF-only 灰度。」

**这句话本身就是一张待办清单。** 我按它拿两个真 docx 打了 docling-serve，30 分钟就把「理论覆盖」变成了「实测覆盖」，并且顺带定位到真正的断点。

**固化**：读 spec 时留意「本期只做了」「未测」「待验证」这类措辞，**它们标记的是最便宜的信息缺口**。

### 例子要能和规则的每个词对上，公式比故事更容易对上

崔扬说：「你对 B1 的举例挺好，但和『类名只能出现在公理的谓词位和注解的参数位』**不能产生直观的联系**。你看下如何能够把规则与示例联系起来。**另外你可以用一些推导公式来举例，这样应该更容易联系。**」

**改法**：把规则里的三个位置名词各对应一组公式，合规标 ✓、违规标 ✗，摆在一起：

```
谓词位，合规：       课程(752468)
注解的参数位，合规：  display_name(课程, "课程")
业务参数位，违规：    完课率(课程, 0.62) ✗
```

**为什么公式比故事好**：故事里读者要自己找「这段对应规则的哪个词」，公式把对应关系摆在版面上。

**而且违规那组要给两个例子**（一个属性 `完课率`、一个关系 `属于企业`），覆盖规则里的「业务属性或关系」两种。

### 写规则的人自己先要当第一个读者

今天被追问出来的四处文档问题，都是这一条：

- **「实体」不是词表里的词，却写进了基石**（崔扬：「基石 B7 里，实体是什么？你是不是使用了不在我们规范词里的词语？」）
- **「需规避」不如「需加校验」直白**
- **例子和规则对不上**（B1 那条）
- **SHACL 解释里用了「字段」这个 RDF 里不存在的概念**，导致「适用于 Course 节点但检查 containsSession 字段」读起来自相矛盾

**固化**：写完一条规则，逐词检查每个名词是不是已经在词表里定义过。**用了词表外的词，就是给读者留了一个必须猜的地方。**

### 换解释器是实质的环境变更，不是绕过障碍的小动作

早上系统 Python 的 tkinter 报错，我的反应是**换一个能开窗的 Python**，而不是先问「以前是用哪个跑的」。结果透明背景和字号全变了。

**根因是我把「跑起来」当成了目标，没问「跑得对不对」。**

**固化**：一个程序原本能跑、现在跑不了，**先查它以前是怎么跑的**，不要先找一个能跑的替代品。**换语言版本、换解释器、换库版本，都要当成变更来对待，做完要验证行为没变。**

### 依赖清单要从代码里读，不能凭印象编

我报告过「requests: OK、tkinter: OK，依赖齐全」，**但那三个文件里根本没有一处 import requests**。我是凭「股票脚本大概要 requests」编了个清单去测的。

这个错误不影响结果，**但那句「依赖齐全」是没有依据的**。

**固化**：`grep -hE "^import |^from " *.py` 一秒钟的事，别猜。

### 验证 shell 脚本的行为必须在脚本声明的那个 shell 里验

`start_stock_watch.sh` 第一版输出乱码，我第一次判断成「后台 nohup 与 stdout 并发写造成的截断」——**错了，它稳定复现了两次**。

**真因是 bash 的 UTF-8 变量边界 bug**，而我第一次验证时是在 Bash 工具的默认 shell（**zsh**）里跑的 echo，**zsh 没这个 bug，所以没复现**。脚本头写的是 `#!/bin/bash`。

**固化**：`bash -c '...'` 和 `zsh -c '...'` 是两个不同的解释器，行为可以不一样。**验证脚本里的一行，要用 `bash -c` 显式指定。**

### 「一个机制看起来在做 A，实际在做 B」这类陷阱要单独标出来

`rdfs:domain` 和 `rdfs:range` **看着像校验，实际是推理**。写了它，数据违规时的结果是**推出一个新事实**，而不是报错。

**这类陷阱的共同形状是：一个机制看起来在拦住错误，实际在接受错误并改写世界。**

**固化**：遇到「声明式约束」时都要问一句：**它违反时的行为是拒绝，还是推导？** 拒绝才是校验。

### 撤回自己说过的话要给台账，不要只说「我错了」

今天撤回了四条，每次的写法都是先给一张「当前有效结论台账」表：

| 结论 | 状态 |
|---|---|
| 类不能出现在业务属性或关系的参数位 | 成立 |
| 「凡是有标题的都是课程」 | **撤回**，错的，理由见下 |
| 属性以类侧公理表达 | 新结论，本轮给出 |

**这张表让崔扬一眼看出「哪些还成立、哪些没了、新增了什么」**，比一段解释有用。

### 判据②防不住「被清空」这一类

这已经是第二次「远未到期却全体消失」（8/28、今天）。**判据②（满 4 天主动续期）防的是到期消失，防不住被清空**；而自愈检查每 3 天才跑一次，**最坏情况会漏掉近 3 天的全部任务**。

真正的修法是持久化到磁盘，**但 `CronCreate` 明确写了 `session-only`、`durable` 参数无效**。

**在这个限制下，唯一可靠的兜底是崔扬发现不对时手动喊一声。** 这一点要如实说，不要假装判据②能覆盖。

### 全量重建的时刻选择有讲究，今天的选法可以复用

**10:35 BJT 是好时刻**：三条板块任务（09:30/09:45/10:00）当日已触发完，尾盘（14:45）和日内（15:30）还没到。**重建后三次全部按点触发，没有误触发。**

对比：9/1 那次选 09:12，**正落在板块任务窗口中间**，`sector_morning_0930` 当时尚未触发，删除重建可能导致丢失或重复。

**固化**：全量重建要选一个「刚过去一批、下一批还远」的窗口，并且事后要验证下一批是否按点触发。
