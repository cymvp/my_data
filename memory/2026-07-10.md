## 1. 今天获得的知识与技能

**"知识点首末次提升"指标的作用**（reporting）：定义 = 最近一次正确率 − 首次正确率（数据来自 `workspace_knowledge_point_data` 的 `first_correct_rate / last_correct_rate`，库里预算好）。它和"知识点正确率"**配对使用**——正确率给"现在弱不弱"的横截面，首末次提升给"练了有没有效果"的变化量。单看正确率区分不了"低分但在进步"（继续练）和"练了也没提升"（得换方式补练）这两种要用完全不同干预的情况。

**Slack 的 summary 能力边界**（研究实证，不凭记忆）：Slack AI 的 Summarize channel / Recap 是**付费插件、面向用户个人的 UI 功能，没有可程序化调用的 API**，摘要拿不到、不能作为"可发布对象"接进流程。业界通行做法是用 `conversations.history` API 拉消息、喂自己的 LLM 生成摘要。所以"每日 summary"必须自建，不能依赖 Slack 自带。

**CSRS dataset id 的生成机制**（.36 部署中摸清）：dataset id = `uuid5(NAMESPACE_OID, dataset_name + owner.id + tenant_id)`——确定性哈希。但 tenant / agent（Principal）的 id 是 `uuid4` 随机的，所以"同名同 owner 重建能得到同一 dataset id"**不成立**（依赖那两个随机 id）。要跨机保住写死的 dataset id（`6eee9255-cdb1-5624-83a8-17a117a11495`），只能显式钉 id 重建：先建空库、用 FK 安全法（copy 新 id 行 → 改 acls/dataset_database/dataset_data 引用 → 删旧行，一个事务，因 FK 是 `ON UPDATE NO ACTION` 不级联）钉住 id，**再上传文档**（cognify 会按 dataset_id 给 Milvus/Neo4j/ES 打标，先传后改 id 会导致检索对不上）。

**rootless sshd 部署的三个坑**（写进了幂等脚本 `~/projects/my_scripts/setup_rootless_sshd.sh`）：① 防火墙——CentOS firewalld 默认 REJECT 非放行端口（refused 而非 timeout 是 REJECT 特征），要 `firewall-cmd --add-port` 放行，别用裸 `iptables -I`（reload 会冲掉）；② `StrictModes=yes` 要求家目录和 key 文件不可被组/他人写，否则认证被拒；③ 粘贴超长 RSA 公钥会折行损坏 keys 文件，要用 `printf '%s\n'` 单行写入。admin 无 root 时在家目录跑 rootless sshd（端口 >1024、`UsePAM=no`）。

**macOS TCC 隐私保护**：`~/Downloads` 可能被系统级 TCC 拦住，进程内 `cp`/关沙盒都绕不过（EPERM），要么用 Finder 拖文件、要么给终端 App 开"完全磁盘访问权限"。

## 4. 今天获得的经验与教训

**先研究再动手，尤其涉及服务器/id 的写操作**：复刻售后库时，一开始以为"同名重建 = 同 id"，实际反算 uuid5 怎么都对不上，深查才发现 tenant/agent id 是随机的、dataset id 被显式钉死。教训——涉及确定性 id、跨机迁移这类，先把生成机制和数据现状摸清楚（读代码 + 查 DB + 本地验算），别按直觉动 DB。用户也纠正过一次顺序："先建库上传再改 id" 会导致向量/图/ES 打标对不上，必须先钉 id 再上传。

**文档写给团队看，不用视角不清的"你/我"**：内部知识库计划文档里被要求把"你/我"全改成明确的人名（崔扬、王继勇、陈婷婷），因为文档对象是团队成员。这和 reporting 材料里"不用给个人看的'我们'"是同一条原则——多人/对团队的材料要写明角色。

**会前把框架做扎实，会上讨论自然落在框架里**（演讲复盘验证）：PM 会成功的关键是开场三句话给了议程（回答什么/怎么回答/底下建什么），加三个准备好的示例问题，全场讨论都挂在这个框架上、当场落定了分工和切入点。反面提醒：讲"前两层数据基本够"时被 CTO 补充"有数据 ≠ 有数据产品"——容易被挑战的简化表述，下次自己先讲精确版，不留给别人补。

**业务认知（会上收获，对产品判断重要）**：① 效果证明不必做严格归因——绝大多数培训是普通的，客户要的是"从普通培训里找出可向上汇报的亮点"，几个正面单点例子价值就成立；② 复合指标能不能成立先看业务认不认这个叙事（如健康手环睡眠分），算法精确度在其次；能力评估用档位、不打 89/90 这种没人说得清的精确分；③ 培训负责人大多没有测量方法论、问不出好问题，产品要主动摆出关键指标和洞察、再引导追问，不能只做被动问答。

**AI 味要在落笔时就防**（更新 /ycui_deslop 的核心教训）：连日文档 AI 味反复出现，根子是"写完再洗永远慢一拍且洗不干净"。所以 skill 改成初次落笔就对照 10 类 + 第 0 步先定文体/读者/正式度。cuiyang 对文档质量要求高、反感科普博客腔（"业界走过三代"）、口号腔（"第一刀切最薄"）、填充句（"一口答不了"）。
