- **"改本体不改代码"这条原则的真正判据（今天被用户追问、并纠正了我的误读）**：prove 的 CLAUDE.md 原文是"加指标、加 CQ、加 join 路径都在 ontology/ 里登记完成；**发现必须改代码才能加指标时，先说明为什么**"——它要求的是"先摆理由讨论"，不是"绝对禁止改代码"。我此前说"硬登记就违反原则"说重了、替用户下了结论。这条原则值得坚持的三层理由：① 交付速度（登记一条 YAML 就能上线，和改代码才能上线是两种产品形态，后者对业务方就是"又一个要排期的需求"）；② **口径可审计性（最要命）**——编译器里的特例是注册表看不见的，一旦口径一半在 YAML、一半藏在 `if metric_id == 'xxx'` 里，注册表就不再是唯一正本，且没有机制保证两边一致；③ 这个仓库付过一次代价（任务列表里就有"24 指标全量迁 DSL、删除 chain.py 六个特例机制"，那六个当初也都是"就这一个指标特殊一下"进去的）。**真正的判据不是"能不能改代码"，而是"这个特判是某个指标独有的，还是一类指标共同的能力缺口？"独有的先别登记；共有的应该扩展 DSL 让所有指标受益——那不叫加特例，叫补能力。**
- **"小节完成率"的分子分母粒度不一致（页面口径坑，容易搞反）**：UMU 课程概览页的小节完成率是 `min(round(小节完成人数 total_finish ÷ **课程总参与人数 total_student** × 100), 100)`——分子是小节级、分母是**课程级**，粒度不同，所以某个小节的完成率会被更大的课程总参与人数拉低。小节参与人数确实存在（同一条 SQL 里 `COUNT(*)` 算出的 `total`，条件 `complete IN (2,1)`，和完成数共用一次聚合），但**它没被用作完成率的分母**。"小节完成人数 ÷ 小节参与人数"这个看起来天经地义的算式，页面上并不存在。

## 4. 经验与教训

- **不要替用户把结论下了——引用他自己定的规则时更要读准原文**：我说"硬登记 `total_finish` 就违反『改本体不改代码』"，但用户 CLAUDE.md 的原文留了口子（"必须改代码时，先说明为什么"）。规则要求的是摆理由讨论，我却当成禁令否决了一个选项。**引用用户的规则/文档作为论据前，先把原文读准，不要凭印象加强它的约束力。**
- **"同一个坑第三次出现"就该改机制，不是再修一次**：满分（full_mark）写默认值 100 的坑，今天在 demo 层是本会话第三次遇到（前两次在指标声明和评测参数）。这类"允许写默认值的关键参数"迟早会被写错，而且**每个数字看着都真、对账查不出来**。判断原则：同一类错误出现第三次，说明是机制允许它发生，该去掉那个允许（比如强制从 `exam_full_mark` 指标查、不给默认值），而不是再修一处。
- **没有证据就不编溯源内容，宁可留空**：文档要补 37 条指标的页面清单，我扫完发现大多数没有真实证据支持，明确拒绝批量补——**把猜测写成溯源文档比漏写更糟**。同理，作废的缓存标记作废而不是手改数字（缓存是算出来的结果，手改就是造假）。
- **代码链路是比抓包更可靠的证据**：确认"进展趋势页的完成人数走哪条链"时，直接读后端代码追到 file:line 比开浏览器抓接口更快更确定。抓包只在需要"完整页面接口清单"时才必要。
- **抗跌/横盘不是安全的证据，要区分结构性和质量性**：长鑫在全球存储崩盘中逆势涨，是流通盘 6.7%、新股情绪、国产叙事、散户定价四个机制撑的，不是基本面更好——而且它 PB 29 倍是三星近 10 倍。**在下跌市里"能不能跌"是按流动性和定价体系分的，不是按质量分的。** 如果因为"它抗跌"就觉得它安全甚至想买，这个推理本身是陷阱。给用户做判断时要把机制拆开讲，不能停在现象。
- **给有回本焦虑的用户做投资分析，要敢反复 push back 且守住边界**：用户连续问"红利 ETF 一周能不能赚 5%""3800 有支撑是不是不会跌了""长鑫抗跌是不是更好"，这些都是套牢后的回本焦虑在找理由。有效的做法是用数据讲清矛盾（防御品种的低波动是双向的、给不了 5% 上行；支撑位是护盘护出来的、事件面前会破；抗跌是结构性的），而不是顺着找标的。同时守住边界：不做方向预测、不给具体买卖指令（不是投顾）、只给决策框架和风险量化。
- **时段与模式不匹配时要明说、不机械执行**：cron 触发的"早盘模式"在 11:32 才跑，此刻开盘方向预测已无意义（方向兑现两小时了）、重复发 Slack 是过时内容——正确做法是说明情况、改按盘中模式给有用的分析。同理尾盘建议在 11:33 给，要标注"数据是上午收盘、下午若剧变需复核"。**skill 的"以 prompt 为准"不等于无视现实时点，要把差异如实告知。**
- **git 的错误信息可能误导，同类操作对照可快速定位**：my_data 的 `git pull` 报 "correct access rights and the repository exists"（听起来像权限/仓库不存在），实际是瞬时网络卡顿——判据是同一个 SSH key、同一账号的另一个仓刚刚 push 成功。**建议给 sync 类脚本加 `GIT_SSH_COMMAND="ssh -o BatchMode=yes -o ConnectTimeout=15"` 和 `GIT_TERMINAL_PROMPT=0`**，让网络不通快速失败而不是挂住，也避免 git 弹交互提示卡死。
- **投研调研要甄别"题材"与"业务实质"**：华通线缆的"机器人电缆"题材与它无业务实质（属华菱线缆/鑫宏业），真实支撑是 70% 海外收入 + 安哥拉电解铝项目。做个股调研时，市场流传的题材必须逐条对回公司的实际业务和收入结构，否则会把别人的故事算到它头上。
