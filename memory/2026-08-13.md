### 今天最通用的一条：否定命题要穷举，肯定命题找到一处就成立

要证明「`where` 里不支持结构化引用枚举」，解析注册表时只找了 `enum` 这个键，漏了 `enum_value`，于是下结论「不支持」。**实际早就支持**，而且是加载期解析、编译器一行不动。

**判据：凡是要下「没有 / 不支持 / 零消费者 / 从未生效」这类结论，先问一句「我穷举了吗」。** 肯定命题（「有一处在用」）找到一处就立住；否定命题要求穷举全部可能的键位。

**同一种错法今天犯了三次**，而且都不是「用 grep 数词频」那个病——三次都在解析结构，错在**枚举键位时漏了分支**：

1. 漏掉 `warehouse.fields`，把列级 `concept` 的 22 处数成了 4 处
2. 拿声明旁边的 `caveats` 当当前状态
3. 只找 `enum` 键、漏掉 `enum_value`

**举个例子说清这个区别**：你让人清点一栋楼里有几盏灯没关，他挨个房间看了（这是解析结构，不是数词频），但他只看了标着「办公室」的门、没看标着「会议室」的——报回来的数是真数过的，只是**范围少了一类**。

### 缺的不是知识，是结构化形式

`ontology/rbox.yaml:40` 的关系 `examHostedBySession`，描述原话已经把要用的知识写全了：

> 考试的承载形式；`exam_type=exam_session` 时考试寄宿在课程小节上（`vote_session.type=10`，**两者共用同一个 `session_id`**），`daily_exam` 型考试不经过小节、独立存在

**条件（仅 exam_session 型）和反例（daily_exam 型不经过小节）都在里面。** 缺的只是机器可读的那一面——`mapping-registry` 里那 16 条关系的物理映射没有它，所以程序读不到，今天靠人读注释才知道。

**所以做法是给这条已有关系补上物理映射，不新增声明。** 这个区分不是措辞：按「新增声明」去做，`examHostedBySession` 就会变成**第二条被架空的关系**。第一条是 `examSessionOfCourse`——「从考试找课程」这件事有四种表示（关系声明、两份同名硬编码函数、lookup 检索），**唯一不生效的恰恰是关系那一份，因为每个消费者都绕过它另造一份**。

最终形态简单到不需要任何新键名：

```yaml
- relation: examHostedBySession
  steps:
    - entity: session_dim
      join: { from: id, to: id }              # 考试的标识列 = 小节的标识列
      where: [ { use: exam_session_kind } ]   # 条件引具名过滤器，不写 type=10
```

### 走关系查一次 vs 把数字抄过去（工牌号与门禁卡号）

一个人的工牌号和他的门禁卡号恰好是同一串数字。你可以在制度里写一句「这两个号相同」，以后直接拿工牌号当门禁卡号用；也可以每次去门禁系统里查一下这张卡在不在。

**前者省一次查询——但如果这个人其实没办门禁卡，你会拿着一个不存在的卡号去开门，而且没有人会报错。**

`daily_exam` 型考试就是那个没办门禁卡的人：它根本不寄宿在小节上、没有对应的 `session_id`。走关系查一次，查不到就是查不到；抄数字，抄出来的是个假 ID。

**顺带一个收获**：原先担心加载期校验 V5（检查参数名与 `identified_by` 一致性）会把「两个名字指同一个值」误判成不一致、需要开豁免。走关系之后这个担心不成立——考试域参数一律叫 `exam_id`、课程结构侧一律叫 `session_id`，各自和自己的概念对得上。**少一处豁免就是少一处以后会漂的地方。**

### 静默失败长什么样（货架编号与拣货单）

仓库把货架编号从「A 区」改成「1 区」，但拣货单还印着 A 区。**拣货员找不到 A 区，他不会停下来报错——他把整个仓库的货装一车推给你，你看着满满一车，以为货齐了。**

系统里对应的是：参数名认不出来 → 被剥掉 → 指标返回不带过滤的全量数据 → 模型照全量作答 → 数字对账全过。

**这个形状本仓踩过四次**（三次企业 ID、一次分组维度）。所以注册表改名与代码跟上那两步的验证必须验「**参数有没有真的生效到查询上**」，只验「参数解析出来了」不够。

### 当「答对」需要先放宽期望值才成立时，先假定是没修好

一道已知失败题答对的两轮选的是 `by_completion`，而题面期望写的是 `by_action`，看起来像是期望写窄了。查注册表：

| | `by_action` | `by_completion` |
|---|---|---|
| 源表 | `participate_course_detail_bi` | `data_course_completion` |
| 定义 | 有任意学习行为事件的学员去重 | 完成度表有未软删记录的学员去重 |
| `routing.hint` 原话 | **「课程参与人数的问答默认口径」** | 「总体概览页面显示的参与人数口径」 |

**注册表自己声明了：问答走 `by_action`。** 而那道题问的是「有多少人参与了学习」，不是问页面。**所以那两轮不是答对，是选错了口径**——两个口径取自不同的表、算的是不同人群，数字必然不同。这就是本仓头号错法的形状（**数字真实、口径不是你要的那个、对账查不出来**），只是从「粒度错」移到了「口径错」。

**判据：放宽期望是唯一一个既能让红变绿、又不改任何实现的动作，所以它必须多过一道关。**

### 「修绿」和「跟着设计改」的两条区分标志

**标志一**：修绿是「红消失、声称的保证不变」；正确的做法是「**声称的保证缩到真话，红因此消失**」。

实例：V5 的第一版测试断言「把解析器参数改回 `session_id` 应当报错」，实测没报（因为 `session_id` 本身是合法标识）。**处理方式不是把断言改成能过的形状，而是把断言缩到实际保证的范围，再把缺口记成欠账。**

**标志二**：**为改动带来的新缺口补了一道会响的守卫，而不是把旧断言删掉了事——修绿的人只删，不补。**

实例：旧测试证明「判据不是写死的名单」，而那个证明依赖后缀判据，新设计**故意**放弃了这条性质。留着旧断言等于让测试反过来规定设计；而判定它不是修绿的依据，是它同时补了新守卫。

### 能被重跑掉的信号，重跑之前先把它记下来

十问验收有一轮 gate 违规——**回答里出现了证据里没有的数字**，形态（`-90.0`、`23.0`）像是模型自己做了减法，**那是本仓头条禁令（LLM 不产生数字）**。

有人提议把判据改成「两轮都失败才算红」。**反对的理由是它认错了信号是什么**：那轮失败是机制抓到一次真实违规，不是测试抖动。「重跑就绿」会把一个间歇性的产品缺陷变成不可见——而这正是消融实验上反复摔的那件事：一个会漂的量，重跑几次总能取到好的那次。

**处置：单轮红就是红；诊断程序固定下来；关键是每次 gate 违规都要落盘，让发生率可测。** 今天只知道「两轮里有一轮」，**而这个比率没人记，所以没人知道它是 1% 还是 30%**。

顺带一个含义：三种失败机制里有一种是评测集早记着的约 15% 概率事件，**所以「十问 10/10」这条纪律本身带噪声**，而落盘正是把噪声和回归分开的办法。

### 存在性断言会因形态改变而误报

`tests/test_relation_path_canon.py:142` 是一条**存在性**断言（`assert kind_preds`）。把 `type=10` 从字面量改成枚举引用之后，只认字面量的匹配器找到 0 个、断言变红，**而谓词其实还在**。

**所以更新匹配器是在修一个误报，不改才是错的。** 判断它没有削弱保护的依据：匹配器同时认两种形态，谁把裸的 10 抄回去就是 2 个位点、直接红（做了变异验证）。

### 校验判据要落在列上，不是落在实体上

一个被否掉的方案：放宽编译器的资格校验，判据是「anchor 参数名等于**终点实体所属概念**的 `identified_by`」。

**这个判据放行一个语义错的形态**：绑定列换成 `exam_session_dim.course`（课程外键）时，实体的概念还是 Exam、参数还是 `exam_id`，照样放行——**而那正是原校验要拦的错，只是换了位置发生**。

**根因是判据落在实体上，而一张实体上有多个概念的列**（那恰恰是列级概念声明的前提）。正确形式：**被绑定那一列声明的概念，必须等于 anchor 参数所标识的概念。** 而这句话 `semantic/compiler.py:742-746` 的注释里已经写了。

**所以路径是先做列级概念、然后把那条校验整个替换掉，而不是放宽。** 放宽等于保留「按字段名猜主键」的推断再加例外；替换能把 `_entry_terminal_pk` 整个删掉——它的 docstring 自己写着「彻底的做法是列级概念声明，单独立项」。

这也回答了「改编译器算不算破纪律」：**纪律防的是「为加一条指标去写代码」，这里做的是反向——把靠字段名猜的代码换成读本体声明。**

**但删掉那个推断有个前置条件**（扫描每个实体的标识列）：标识列已挂概念 6 个、**没挂概念 8 个**、按名字推断不出标识列 13 个。那 13 个今天本来就不拦，换成列级概念行为不变；**但那 8 个今天猜得出主键、校验会拦，换成列级概念后查不到概念就不拦了——那是把校验放松**。所以判据改成可机械枚举的形式：**删掉推断之前，凡是能出现在 entry 终点位置的实体（就是 16 条关系映射的 `steps[0].entity`），标识列必须已挂概念。** 而且别把那 8 个都当欠账补——其中一半（提交、选项这类）的标识列本来就不该有概念，补出来的会是**为了让校验过而发明的概念**。

### 一对对偶的歧义采取两种态度，后一种一定是漏的那个

| 形态 | 现在的处理 |
|---|---|
| 一个概念，两列实现（V2 校验） | 禁止，响亮失败 |

`git add -A`、`git add -u <目录>`、以及归属脚本里「认不出就归自己」。**共同点都是把「提交范围」这个判断交给工具。**

### 给模型喂确定性抽参结果，和拿模型输出校验模型自己，是两类东西

前者是**问句文本的确定性函数**，模型碰不到；后者是闭环（结论与判定前提来自同一次输出），已经因此下线过一个校验。

**但这里埋了一个下一步会触发的陷阱**：新载荷只加在目录路由，而可达性守卫只在 CQ 路由，两条路径今天不相交。**一旦给目录路由也加上可达性守卫，守卫要评判的那个模型已经被告知了守卫自己的答案**——它几乎永远不会红，绿色不再有信息量。

### XFAIL 会掩盖失败方式的退化

那两道已知失败题里，第二道 8/13 复测时刚从「拿小节级指标顶替作答」改善成了「拒答」——按本仓纪律那是正确方向。

而新机制的参数补全实测产物是 `{'course_id': ('course_of_exam', ['exam_id']), 'session_id': ('session_of_exam', ['exam_id'])}`，**所以问句一点名测评小节，`session_id` 从此一定会被补上**。小节级指标从「缺参数跑不了」变成「跑得了」，很可能退回去给一个小节级数字。

**这不是变糟一点，是失败方式从响亮退回安静。** 而且**这个退化在总分里看不出来**——那两题是 XFAIL，「拒答」和「答错对象」都算不通过。**必须专门跑前后对比，不能等总分。**

### 一个「凭空出现却看起来完全正常」的 ID 是怎么可能的

有人在 docstring 里写「目录检索（`course_catalog` 那种）自然落选：它的输入是名字关键词、不是某个对象的 ID，所以 `ins` 为空」。**实测不是这样**：`course_catalog` 的输入是 `where=['enterprise_id']`，不空。它落选是因为**输出列别名叫 `id` / `title`，不在可点名参数集 `{course_id, exam_id, question_id, session_id}` 里**。

**为什么这不只是一句话写错**：把课程目录的输出列从 `id` 改名成 `course_id` 是一个**再自然不过的重构**。改完之后，`course_catalog` 就成了一条「输入 `enterprise_id`、输出 `course_id`」的 ID 填充检索，于是任何带企业上下文的问句都会去跑它，**并把 `course_id` 填成这个企业课程列表的第一行**——一个凭空出现、看起来完全正常的课程 ID。

今天它还多一层偶然保护：`enterprise_id` 在不在 `params` 里取决于调用方怎么传。**两个偶然合起来守着一条安全性质，这就是该换成结构判据的信号。**

修法：把输入也过一遍可点名参数集（那条规则已经把隔离轴的概念排除掉了），`enterprise_id` 自动落选，**那句 docstring 也就变成真的了**。

**判据：「谁是被点名的对象」和「谁是调用方给的上下文」不是一回事，而这个区分注册表里已经声明了。**

### 已知失败用例需要第三态

判据原先只有对错两态，于是一道**查清了但暂时不修**的题只有两种下场：改期望值修绿（等于把缺陷从记录里删掉），或者让评测长期带红（红久了没人看）。

**加了第三态**：题照跑、失败记 XFAIL、不进通过率分母，**一旦它通过就报 XPASS**——那要么是有人修好了、要么是期望值漂了，两种都得有人看一眼。
