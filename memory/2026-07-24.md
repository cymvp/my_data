## 1. 今天获得的知识与技能

- **DSL（Domain-Specific Language，领域专用语言）与语义层**：为某个领域设计的受限小语言（正则、cron、SQL 都是），表达力刻意受限换来机器可校验。今天在 prove 项目落地了「指标查询 DSL」——用结构化 YAML 声明（measures/dimensions/where/attach/scope/compose）描述"指标怎么算"，由自写编译器确定性翻译成 SQL，全程 LLM 不写 SQL。这是业界"语义层"产品（dbt MetricFlow、Cube、LookML）的极简自建版。
- **为什么 LLM 不写 SQL**：口径知识 LLM 补不了、错了无痕迹，消融实验证否（有本体 15/15 vs 无本体 11/15、一致仅 7/15）。正确架构是 LLM 只做路由选择（从指标目录选 id），SQL 由编译器按登记的映射确定性生成。
- **开源选型结论（查证过许可证）**：零件有、整机没有。dbt MetricFlow（Apache 2.0，2025-10 刚开源）/Cube 验证了"声明式指标+确定性编译"是正路但假设单一数仓、无 NL/治理层；WrenAI/Vanna 最终仍让 LLM 写 SQL（过不了铁律）；Ontop（OBDA/R2RML）理念同源但输入是 SPARQL、RDF 全家桶太重。**决定自建，借三个零件**：SQLGlot（SQL 生成后端）、MetricFlow 的 YAML 词汇（对齐不自造方言）、Ontop 的 R2RML 映射思想。
- **量价/做 T 知识**：追踪网格（中枢随价格移动的网格）比固定网格更能罩住偏离区；VWAP 作中枢太慢（全天累计均价，大跌后一天不跟下来），改用价格驱动（现价偏离中枢 1.2% 就重锚现价）明显更好。做 T 的利润主要来自"趋势日少亏"而非"震荡日多赚"。
- **macOS/环境坑**：本机是 JST（比北京快 1 小时），任何 A 股交易时段判断必须显式用 `TZ='Asia/Shanghai'`/`ZoneInfo("Asia/Shanghai")`，否则 14:45 尾盘线等逻辑整体早触发 1 小时；YAML 1.1 把 `on` 解析成布尔 True（键名别用 on，用 join）；tkinter 模态弹窗会阻塞主循环。
- **本体治理平台的几个概念**（来自 ontology_governance）：KMS 给本体制品非对称签名防篡改（私钥不出 KMS，下游 SDK 独立验签）；GitLab 存本体源码（YAML）+ 承载 MR 审批流；S3 存构建制品（按 content_digest 不可变寻址）；warn/enforce 双模式（dev 默认 warn 不拦截）；fail-closed（APP_ENV=prod 但 AUTH_MODE≠enforce 直接拒绝启动）。

## 4. 经验与教训

- **静默降级是最危险的 bug，且专挑"看起来对"的环境藏起来**：prove 的 course_id 未透传导致课程范围退化成企业范围，本地镜像（只有该课数据）对拍全绿，只有打真实超集数据才现形。原则固化：**参数契约变更必须在数据超集环境验证，不能只信同构镜像的对拍**。
- **时区必须显式钉死**：本机 JST 已经两次坑到 A 股逻辑（定时任务、做 T 尾盘线）。凡涉及交易时段，一律 `ZoneInfo("Asia/Shanghai")`，不用机器本地时间。
- **回测绝对收益率一律当幻觉**：bar 级数据有前视偏差、无滑点，做 T 回测出的 4-5%/天不可信；只用组间相对排名做决策，反复对用户强调，不让其抱错误预期。
- **交易系统不自动改参数**：自检能自动发现+分析+提建议，但改动实盘交易参数（档距/阈值/触发）必须人确认——无人值守自动调参易过拟合、出问题用户不知情。这是对用户资金负责，不是偷懒。
- **用户明确要求"你要主动观测数据、不等我发现问题"**：已落地日终自检 cron。但边界要守住：检测+报告自动化，参数变更需确认。
- **部署/构建脚本用管道接 tail 会掩盖退出码**：ontology_governance 的 bootstrap 在 worker 步失败但 `| tail` 把退出码吞成 0。检查关键步骤成败别用管道尾部判断。
- **调用外部仓库前先读它自己的 run/SKILL**：/run skill 优先找项目自带的启动 skill，比自己摸索可靠。
