### 今天最重要的一条：一个反复出现的错法，同一天犯了四次

**错法的形状是：拿一个容易检测的形式特征，去近似一个语义判据。** 形式特征好搜，但它和判据不等价，而不等价的那部分就是漏检。

四次实例，每一次都是崔扬指出漏检之后才发现的：

| 我用的近似 | 应该用的判据 | 漏了什么 |
|---|---|---|
| 搜问号 `？` | 判「这个标题是不是在设问」 | 无问号的设问。中文标题的设问经常不带问号，比如「怎么证明更准」。搜问号命中 **0**，搜疑问词命中 **6 个标题** |
| 搜「不是 X **而是** Y」完整句式 | 搜「不是」两个字，逐条判 | 「不是 X」单独出现的情况。搜完整句式命中 **1 处**，搜「不是」命中 **26 处、15 处要改** |
| 判「标题是不是陈述句」 | 判「标题在命名位置，还是在跟读者说话」 | 陈述句形式的元信息。「四个收益，后两个比降本重要」是陈述句，但它在跟读者说话。**17 处** |
| 用 grep 近似「读」 | 逐段读 | 「一句话讲了三件事」「用模糊词代替数字」这类结构问题，一条 grep 都不命中 |

**第四次那组对比数字最能说明差距**（同一份文档、同一天）：

| 检测方式 | 「不是 X」 | 「它」指代不明 | 一段塞太多 |
|---|---|---|---|
| grep | 命中 1 处（只搜句首） | 改了 15 处 | **完全没查这一项** |
| 逐段读 | **17 处** | **38 处** | **6 段**（最差 225 字 4 句） |

**逐段读扫出来的问题是 grep 结果的三倍多，而规则一条都不缺。** output style 第二节明写「一句话一件事」，第五节明写模糊词要换成具体描述。缺的是执行时用了不等价的近似。

**固化成通则**（已写进 `ycui_deslop`）：每一类检测都要问一句「我搜的是判据本身，还是搜的是判据的一个容易检测的近似」。

这条和这几天在 roleplay 里反复撞到的另一个形状同源：**规则写在那里，执行时用了一个不等价的近似**。

### 一篇论文给了「AI 味」可计算的量化基线

`arXiv 2603.27006`，《The Last Fingerprint: How Markdown Training Shapes LLM Prose》。它做的是**逐个模型量化**，不是给写作建议，所以比中文写作圈那些经验帖有用得多。

三个数字直接相关（破折号密度，每千词）：

| 条件 | 每千词破折号 |
|---|---|
| 人类写作平均 | **3.23**（区间 0.33–17.12） |
| Claude Opus 无约束 | **9.09** |
| Claude Opus 收到「不要用破折号」这条明确指令 | **0.19** |

**这篇论文还解释了为什么「洗一遍」不管用**：把标题、bullet、加粗这些格式标记压掉之后，模型会把痕迹**挤到别处**，破折号是最后残留的那个出口。所以单条禁令会让痕迹位移，必须给出清单而不是逐项禁。

**拿这个基线量自己写的文档**（`rag-eval-brief.html`，去 HTML 标签后 10364 汉字）：破折号 47 个，按 1.75 字/词折算约 5.9 千词，即**每千词 7.9 个**——人类 3.23，我 7.9，接近 Claude 无约束的 9.09，**超标 2.4 倍**。

写进禁令之后归零。**和论文测出的 9.09 → 0.19 是同一个现象**：明确的字符级禁令有效，风格描述无效。原来那条规则失效的原因是它描述的是风格（「节奏单一」），自查时判的是「有没有连续三段同形」，答案是没有，就放过去了。**判据得是能数的东西。**

### 句长统计的两个坑

**一、必须先剔掉表格。** 第一次算出「句长标准差 23.2」，看起来变化度很好——但那是假的：表格内容被拍平当成了句子，最长的两个「句子」分别是 256 字和 200 多字的表格行。

**二、用中位数加 MAD，不用平均加标准差。** 标准差对超长离群值极敏感，一行表格就能把它撑上去。剔表格后的真实分布是：中位数 27 字、MAD 11 字、四分位 17/27/39 —— 落在人类区间内，不是问题。改完之后中位数 24 字、MAD 9 字。

### 标题命名内容，不跟读者说话

从崔扬指出的两个例子里提取出的判据：**把标题单独摘出来放进目录，看它是在命名一个位置，还是在跟读者说话。跟读者说话的就是错的。**

**标题里不许出现的四类：**

| 类别 | 例子 | 为什么不行 |
|---|---|---|
| 章节计数 | 四个收益 / 三个代价 | 名词本身够了，数量往下看就知道。**而且会过时**——加一条就要改标题 |
| 相对位置和顺序 | 另一个优化方向 / 先说 token 怎么算的 | 章节一重排就错了 |
| 阅读指令 | 先分清 B 和 C / 口径声明，先读这个 / 注意 | 标题的职责是命名，不是指挥读者的阅读动作 |
| 内容之间的排序评价 | 后两个比降本重要 / 第一个是真风险 | 这是读完才能验证的判断，写在标题里是预告；而且它评价的是内容组织，不是内容本身 |

**允许的两种形状**：裸名词短语（`收益`、`代价`、`B 和 C 的区别`）；一个完整论断（`记忆提取不该每个应用各造一份`）。

**这两种的分界**：论断作为**主题**可以进标题（这一节就在论证它）；判断作为**对内容的评价**不行（「后两个更重要」评价的是列表项之间的关系，不是这一节的主题）。

**一条加强**：成对的章节用对等的裸名词。`收益`/`代价`、`待查项`/`待拍板项`，目录里一眼看出对称。而「四个收益，后两个比降本重要」/「三个代价，第一个是真风险」看不出对称，因为两个标题各自长成了不同的句子。**这一条和 output style 第四节「对比两个方案时用对等的命名」是同一条规则**，那里说的是表格列名，这里是章节名。

### 角色定义（「你是高级技术工程师」）对今天这七类问题作用为零

崔扬问的是要不要给 AI 加个角色定义。逐条核对今天改的七类问题，**一类都拦不住**——因为这些不是「口气不对」，是具体的句式和结构错误，而角色定义调的是词汇和语气的分布，调不了句式。

**更麻烦的是它可能反向拉**：「高级技术工程师写文档」这个角色在训练数据里对应的文体，大概率包含正式开场（「本文档旨在」）、「综上所述」「值得注意的是」、分点罗列多于成句推理、英文术语不译、以及 `A → B → C` 的流程写法。**最后一条尤其明显**：工程师写文档爱用箭头，而箭头代替推理是 output style 明确禁止的。

**角色定义之所以有时候有用，是因为它间接传递了「读者是谁」和「文体是什么」。** 而 output style 第五节直接就要这两样。**「你是谁」不可核对，「给谁看」可核对**——后者严格更好，因为「给谁看」的答案能直接推出该不该铺背景、术语要不要解释；而「你是高级工程师」推不出这些。

**替代建议**：把「写给谁看」从自律条款变成**留痕的动作**——文档开头写一行。这样动笔前逼自己想清楚，写完之后还能拿它当判据核对。

**三、`ycui_deslop` 两周零调用，查清了原因**

三条原因叠加，每条单独都足以让它闲置：

1. **触发条件要求人先感知到问题**。触发词是「去 AI 味」「这篇文档读起来费劲」，这要求先读完、先觉得难读、再想起有这个工具。但更可能的反应是直接说「这段我看不懂」，那会走到 `ycui_explain`（22 次）。

## 4. 经验与教训

### 每一类检测都要问：我搜的是判据本身，还是它的一个容易检测的近似

**今天同一个错法犯了四次**（详表见第 1 节）。这是今天最该记住的一条。

搜问号近似搜设问、搜例句近似搜句式、判陈述句近似判元信息、用 grep 近似「读」。**形式特征好搜，但它和判据不等价，不等价的那部分就是漏检，而且漏检量级不小**——grep 与逐段读在同一份文档上差了三倍多。

**代理指标可以留，但必须写明它只是预筛，不能代替逐段读。** 已经写成三条可检测的代理：

| 判据 | 可检测的代理 |
|---|---|
| 一句话一件事 | 单句 ≥2 个连接词（因为/但/而/所以/；）且 >44 字 |
| 一段一个论点 | 段落 ≥4 句且 ≥110 字 |
| 不用模糊词代替数字 | 词表：不便宜/难看/一些/较为/大幅/明显/不小/差不多/大致 |

### 规则要写成能数的东西，不能写成风格描述

破折号那条原来写的是「节奏单一：句句都是破折号补一句」，判据是「连续三段以上同形」。**这条约束不到任何东西**，因为 47 个破折号分散在全文，没有连续三段同形，自查时答案是「没有」，就放过去了。

改成字符级禁令之后立刻归零，**和论文测出的 9.09 → 0.19 是同一个现象**。

**判据是能数的东西，规则才有约束力。** 「读起来费劲」不能数，破折号密度、疑问词个数、代词个数能数。

### 数「有没有被使用」必须解析结构，文本搜索会给出反向结论

今天有个 4511 比 0 的极端例子（详见第 1 节）。**skill 列表每一轮都被注入 system prompt，所以文本提及数只反映会话轮数。**

**这条规则本来就写在 CLAUDE.md 里，今天是第一次在真实场景里救回一个判断。** 以后凡是「这个东西有没有被用过 / 用了几次」，一律按 `<command-name>` 这类结构化字段计数。

### 「谁在配置里」和「配置指向哪里」是两个问题

CSRS 那个频道，崔扬说「以前应该加过」但感觉没加成。**它确实在配置里，问题在于 `datasets` 指向了一个只有 2 份文档的测试库。**

**「在不在」和「配得对不对」要分开查。** 如果只回答「已经在了」，用户会觉得我没解决问题；如果只回答「我加上了」，那是错的（本来就在）。正确的做法是先说「已经在了」，紧接着给出「但它查不到东西的真实原因」。

**这条可以推广**：用户报告「某个东西没生效」时，先分清是「没配」还是「配了但指错了」。这两种的修法完全不同。

### 改配置之前要查清连带的校验规则

方案 A 看起来只是改一个 `datasets` 字段，但配置校验要求 `ingest` 必须在 `datasets` 里。**如果只改一个字段，加载期会直接报错。**

**在提方案的时候就要把连带项说出来**，而不是等用户选完了才说「哦还有个问题」。今天是选完 A 之后我才补的那句「方案 A 有个连带问题必须先定」——顺序反了。

### 自律条款靠不住，要变成留痕的动作

output style 里那条「下笔前先定文体、读者、正式度」是自律条款。**今天写了三份文档，一次都没显式定过这三件。**

替代做法：**文档开头写一行「写给谁看」**。写出来之后有两个作用——动笔前逼自己想清楚，写完之后能拿它当判据核对。**比「你是高级技术工程师」这类角色定义有用，因为它可核对。**

同样的形状出现在 loop 任务上：判据②「满 4 天就续期」是可执行的规则，而「注意别在任务窗口内重建」如果只写在教训里就是自律条款——今天就违反了。

### 维护性任务不要排在被维护对象最忙的时候

`loop_checker` 的 cron 是 `37 9 */3 * *`（JST），加上延迟正好落进早盘窗口，而它要维护的三条板块任务就在 09:30–10:00 BJT 触发。**结果今天的重建带走了 09:30 那一轮。**

**判据很简单：维护任务的执行时刻，必须落在所有被维护任务的触发窗口之外。** 已建议改到收盘后 `37 16 */3 * *`。

### prompt 里的第一人称会指向错的人

修 `/ycui-gen-work-summary` 时发现的：文件里写「从**我**自己的角度写」，语法上「我」是用户；但素材在会话记录里，动手的是 AI。**代词说的是用户，证据说的是 AI**，这个矛盾一出现句子就顺着素材滑过去。

**修法必须两条**：① 点名到人（「『我』指使用者 cuiyang，不是你（AI）」）；② 给出素材转换规则（「你查到了 X」→「我今天弄清楚了 X」；只有 AI 才会有的经历一律不写）。

**参照物是 `ycui-daily-memory`**：它直接写「供未来 AI Agent 了解 **cuiyang** 的上下文」，点名到人、没用代词，所以没这个毛病。**以后写 prompt 类配置，涉及视角的地方一律点名，不用代词。**

**注**：这个修改**效果还没验证**——prompt 类改动只能在真实调用中看。

### 用调用记录决定删哪个重复文件

四对重复文件，逐字节相同，删哪个？**不靠命名规范猜，查调用记录。** 数据很干净：四个 `ycui-` 前缀的副本历史调用全部为 0，被真正用过的是另外那四个。

**删之前先备份到 scratchpad。** 今天备份在 `removed-duplicate-skills-20260901/`。

### 一个数据源错了，要检查同源的其他数据

早盘那次，我先发现 KOSPI 错了（老问题），然后才发现 **NDX 和 SOX 也错了，而且它们才是主信号**。三个都走 Yahoo。

**教训：确认一个数据源有问题之后，要把同源的所有数据都过一遍**，不要只修已知的那一个。今天还留了一个没查成的——SK海力士 +0.12% / 三星 −1.35% 来自同一个脚本，我没能独立验证，按存疑处理了。

### 交叉验证要用不同机制的两条证据

SOX 那个数用了两重验证：**指数本身**（`gb_$sox` 现价除昨收）+ **成分股逐个**（NVDA/MU/AMD/AVGO/INTC/TSM）。这两条来自不同的取数路径，指向同一个结论，所以可信。

反例是 `znb_SOX` 和 `znb_NDX`——它们看起来是同一家的接口，但返回的日期是 2025 年，**同一个提供方的不同接口可靠性可以差很远**。

### 分析类结论要主动标出没验的部分

今天两处做对了：SMCI 财报那条明确写「来源可靠性低，且其给的一致预期与 SMCI 近年季度体量不符，我没能独立确认」；CSRS 那条明确写「配置生效已确认，但能不能真查到内容这一步我没验成」。

**没测的就说没测。** 不要让读的人以为整条链路都验过。

### 崔扬会推翻我当天刚写进规则的东西，这不是问题

早上我写「正文里的设问留着」，下午被推翻成「正文也不许」。**规则是在对话中长出来的，不是一次定稿。** 遇到这种情况直接改正本，并把新旧对照写清楚，不要因为「这是我刚写的」而辩护。
