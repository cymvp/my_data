### 相关系数 r 与 p 值：一次被迫讲透的解释

用户看不懂我给的关联性表格，连问四轮。最后沉淀出的解释方式值得复用。

**r（皮尔逊相关系数）是什么**：两个东西同向变化的程度，取值 −1 到 +1。算法是先算出两边各自的平均值，然后每一天问「这一天两边是不是都高于自己的平均、或者都低于自己的平均」——用「实际值减平均值」相乘，同向为正、反向为负，把所有天的乘积加总再除以两边的波动规模。

**p 值在大样本下几乎不含信息，这是关键的一点。** 713 天的样本下，**只要 r 超过 0.074，p 就会小于 0.05**。所以整列 p 全部是 0.0000 是必然的，它只告诉你「关系不是零」，而这个门槛低到没有意义。同一个 r = 0.43，10 天样本 p = 0.178（不显著）、20 天 p = 0.043（刚显著）、713 天 p 约等于 0。**判断强弱只能看 r，不能看 p。**

**判断 r 强弱必须有参照点**，这是我原来漏掉的：

| 比较对象 | r | r²（解释力） |
|---|---|---|
| 新易盛 vs 中际旭创（同行，当天对当天） | **+0.830** | 68.9% |
| 寒武纪 vs 中际旭创（同为科技股） | +0.445 | 19.8% |
| Coherent 隔夜 → 旭创跳空 | +0.441 | 19.4% |
| Lumentum 隔夜 → 旭创跳空 | +0.430 | 18.5% |
| 可口可乐隔夜 → 旭创跳空（对照组） | −0.180 | 3.2% |
| 旭创昨天涨跌 → 旭创今天涨跌 | −0.020 | 0.0% |

**所以 0.43 的定位是「中等偏弱」**：比随便找一只科技股（0.445）强不了，比同行两只票（0.830）弱得多。

**比 r 更好懂的是分档表**，用户看这个一次就懂：

| Coherent 昨晚涨跌 | 天数 | 旭创今天跳空为正的比例 |
|---|---|---|
| 跌超 4% | 88 | **20.5%** |
| 跌 2~4% | 83 | 26.5% |
| 跌 0~2% | 151 | 35.1% |
| 涨 0~2% | 176 | 52.8% |
| 涨 2~4% | 105 | 60.0% |
| 涨超 4% | 110 | **78.2%** |

**关联性的本体就是这个**：不是「美股涨旭创就一定涨」，而是**美股的涨跌能改变旭创高开的概率分布**。而且要指出局限——**中间四档 35.1%、52.8%、60.0% 挤在一起，也就是美股小涨小跌（±4% 以内）时几乎没有区分度，而这类日子占了 713 天里的 515 天、超过七成。**

### 开盘位置 / 收盘位置：两个新增的描述性指标

**开盘位置 = (今开 − 当日最低) ÷ (当日最高 − 当日最低)**；**收盘位置 = (今收 − 当日最低) ÷ (当日最高 − 当日最低)**。取值 0 到 1，1 表示就是当日最高价，0 表示就是当日最低价。

算例（2026-08-03 中际旭创）：今开 891.00、收 902.50、最高 933.61、最低 875.87，振幅区间 57.74 元。开盘位置 = (891.00 − 875.87) ÷ 57.74 = **0.262**；收盘位置 = (902.50 − 875.87) ÷ 57.74 = **0.461**。读法是「开在区间偏下，收在中间略下——当天先冲到 933.61 再砸到 875.87，最后收在 902.50，比开盘高但没守住高点」。

**它们回答了现有指标答不了的问题**：开→收只告诉你终点比起点高还是低，它俩告诉你这一天在自己的波动范围里站在什么位置——高开之后是当天的顶还是起点。

全样本 739 天：开盘位置均值 0.460 / 中位 0.445，收盘位置均值 0.463 / 中位 0.452。**两个都略低于 0.5**，意思是开盘价和收盘价平均都稍微偏向当日区间的下半部分。已作为描述性字段加进 `intraday_guide.py` 的基准。

### 用正态假设从 r 反推分档表，以及它失效的地方

用户问「那张分档表是不是从 0.441 算出来的」。**答案是不是——两者是同一批数据上的两种独立算法**。分档表是数出来的（按 Coherent 昨晚涨跌分 6 堆，每堆里数旭创跳空为正的天数），r 是另一套公式，没有先后关系。

但它们量的是同一件事，所以能互推。假设两个变量都是正态分布，知道 r 就能算条件概率：`高开概率 = 1 − Φ((z门槛 − r × zx) ÷ √(1 − r²))`，其中 Φ 是标准正态分布的累积概率、zx 是标准化后的 x。

**六档验证下来加权平均绝对偏差 4.7 个百分点，四档对得很好，但两档差了 10 个以上，而且都在下跌侧。** 根因是**正态假设不成立**——旭创的跳空分布是右偏的（均值 +0.061%、中位 −0.018%、偏度 +0.817）。**这说明 r 是个只描述线性部分的量，分布不对称时它会漏掉信息。**

## 4. 经验与教训

### 今天最严重的一次错误：口径混用导致我推翻了四张正确的表

**背景**：用户按我给的统计结论开盘卖出中际旭创（+4.5%），收盘 +12.79%，他追问「你的方法真的正确么？虽然 38 只股票都属于科技股、有关联性，但我们本来就是在研究科技板块的涨跌趋势，这种关联性一定要去重么？」

**我做错了什么**：我拿「**日期等权**」算出的置信区间去比「**股票交易日加权**」算出的点估计，得到区间 [41.0%, 57.4%] 不包含点估计 63.8%，**把它当成「发现了严重问题」**，连着推翻了表 A、表 B、表 C、表 F 四张表，还告诉用户他一笔正确的交易「统计上没有依据」。**全部要撤回。**

**两个数回答的是不同的问题**：

- 「随机抽一个**股票交易日**，它落在这一格，触及 −3% 的概率」→ 按股票交易日算 = **63.8%**。**这才是持仓单只票、看单日风险时要的那个数**——板块联动带来的权重是真实风险的一部分，不该抹掉
- 「随机抽一个**交易日**，那天这一格里所有票的平均触及率」→ 按日期等权 = **49.2%**

**用户的质疑是对的**：研究科技板块本来就要保留板块联动，不该为了「独立性」把它去重掉。

**沉淀出的判据**：**区间不包含点估计时，正常只有一个解释——两者算的不是同一个量。这是明确的报警信号，不是「问题很严重」的证据。**

**正确做法**：点估计保持按股票交易日，区间用**日聚类 bootstrap**（有放回抽 N 个日期，把被抽到日期的全部股票一起算）。实测表 A 各格区间宽度变成原来的 1.4~2.2 倍，但**九个格子的结论全部存活**，表 C 的 +0.817% 也仍然显著（聚类区间 [+0.054%, +1.406%]）。

**8 月 2 日那条方法论（同一天的多只票是 1 次独立观察）只适用于「是否显著不同于基准」这类检验，不能用来改描述性概率的点估计。** 这一条已写进 project memory 的 6b。

**还有一条更刺的教训（已记为 6c）**：**第 6 条 2026-08-02 就写好了、连正确方法都点名了，我做新分析时仍然从头到尾没查样本独立性，直到用户拿一笔交易追问才发现。写下来没有自动生效，必须在每次新分析前主动回头对照。**

### 我今天犯的其他错

**配对逻辑有缺陷却先出了结论。** 长假时多个美股交易日被重复配到同一个 A 股日（2023-07-14 被配了 28 次、多出 78 条重复样本）。修正后关联反而更强，而且**连带推翻了另一个结论**——我说过「上涨趋势时光通信票的关联归零」，那是缺陷配对的产物，修正后 Coherent 上涨趋势 r = 0.267（p = 0.0002）显著、不是零，只有康宁真的归零。

**用 `pkill -f` 模式匹配关进程，杀掉了共享服务。** 见第 3 节。

**在 known-issues 里造成重号**，因为没先查 workflow agent 是否已经加过同一条。

**照单次观察给建议。** 我照审阅那一次的观察，建议「把 `refused` 期望与拆分机制对齐」。实际复现三次得到三种不同结果，失败大多不是拒答而是 gate 违规——**改期望治不了，只会把一道会挂的题改成看起来不挂。**

### 今天有效的做法

**被质疑时先去跑数据、不先表态。** 「你说的两点我先各自核实，不先表态」这个开场，后面两点都被证实成立、而且第二点比用户说的更严重。

**用分档表代替相关系数讲关联性。** 用户看 r = 0.43 完全无感，看「美股跌超 4% 时旭创高开只有 20.5%，涨超 4% 时 78.2%」一次就懂。

**给量化结果配参照点，让读者自己判断强弱。** 同行 0.83、随机科技股 0.445、对照组 −0.18，这三个数一摆，0.43 的位置就清楚了。

**主动指出结论的局限而不只是给结论。** 那张分档表两头跨度很大是真信息，但中间四档挤在一起、而这类日子占七成——**不说这一点，用户会以为这个信号天天可用。**

**发现自己的呈现有问题时区分「数据错」和「呈现错」。** 934.44 这个数没错，错的是我只报了它。这两类问题的修法完全不同。
