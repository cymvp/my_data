## 1. 今天获得的知识与技能

**Claude Code 的 output style 是什么。** 它是一个 markdown 文件，放在 `~/.claude/output-styles/`
下，内容会被塞进系统提示，决定 Claude **怎么说**——语气、结构、详略。它不改变 Claude 知道什么。
用 `/config` 里的「output style」项切换。内置三档：Default（简洁工程输出）、
Explanatory（额外加解释）、Learning（边做边学、留 `TODO(human)` 让人填）。

**一个会静默出事的坑，今天恰好避开了。** 自定义 output style 默认**替换**掉 Claude Code
内置的软件工程指令（怎么划定改动范围、怎么写注释、怎么验证工作），不是叠加。
要在 frontmatter 写 `keep-coding-instructions: true` 才是叠加。cuiyang 的
`jiang-ming-bai.md` 已经带了这一行。**没带的人会发现 Claude 的工程纪律莫名变差，
而且不会有任何报错。**

**ASD-STE100 是什么。** 航空维修手册用的受控语言标准，把「说清楚」拆成可逐条检查的条款。
今天被搬成中文版六条：一句话只讲一件事；步骤句不超 40 字、背景句不超 50 字；同一个东西
全篇只用一个名字；主动语态不省主语；不要长定语套长定语；段落不超 6 句。

**「降智」这个说法的根因和大家想的不一样。** 网上普遍归因于模型能力下降，
而查下来至少有很大一部分是输出格式没配——同一个模型换个 output style，可读性差别很大。

## 4. 经验与教训

- **「用户说看不懂」是补救的唯一机会，做错这一轮就白费。** 今天一轮里 cuiyang 说了四次
  看不懂，前三次我的做法是重复原来的措辞再解释一遍，都失败；换一套词从头讲才通。
  规则第六节因此写死：**原来那套词已经证明不通，不许再用。**
- **「不在关键路径上」「省事」「现成」都不是选择理由，只能作为代价说明。**
  今天我用「它的失败方向是安全的」为一处词表判据辩护了三轮，是错的——
  那句话本身没错，但它推不出「所以该留」。
- **「它在别的条件下会绿」推不出「它红是环境问题」。** 今天把一条测试的红判成服务抖动，
  而它其实是我引入的回归；判错的原因是没读测试就归因。
- **靠人记得的纪律一定会忘，而且忘掉时不报错。** 今天修了三处这个形状：
  重录脚本要求「重录后手工把某个例子加回去」、`force_metric_ids` 少清一个条件、
  录制脚本取了一个已经删掉的字段名。
- **配置类改动要先查「这个开关的默认值是什么」。** `keep-coding-instructions` 默认 false
  会静默削弱工程能力，这种坑不看文档发现不了。
