## 1. 今天获得的知识与技能

### 网格交易的根本矛盾：它在你最想赚钱的市况下最不管用

用户的目标是「中际旭创涨到 1400 时赚 70 万」，同时要「每跌 4% 加仓、每涨 4% 减仓」。**这两个要求内在冲突，而且是数学上的冲突、不是执行问题。**

**用这只票的真实历史回测（70 万网格资金、每格 100 股）**：

| 历史时段 | 区间涨跌 | 间距 | 成交次数 | 网格已实现 |
|---|---|---|---|---|
| **单边大涨 近 250 日** | **+401.4%** | 3% | **2 次** | **0.1 万** |
| 上涨 近 120 日 | +70.2% | 3% | 26 次 | 2.0 万 |
| **震荡下行 近 60 日** | −11.4% | 3% | **59 次** | **7.4 万** |
| 震荡下行 近 60 日 | −11.4% | 4% | 44 次 | 7.3 万 |
| 急跌 近 30 日 | −23.8% | 5% | 40 次 | 8.4 万 |

**读法：看第一行和第四行。同样 70 万资金，股价涨 401% 的那段网格只赚 0.1 万，股价跌 11% 的那段赚 7.3 万，差了 70 倍。**

**原因很直接：一路上涨时，网格在低位买的那点货很快就在上涨中卖光了，之后手里只有现金，再也没机会买回来。** 而用户的目标（涨到 1400）正是这种市况。

**网格成本的精确算法**（这个数以后可以直接用）：

```
往返费用率 = 佣金万2.5×2 + 印花税万5（仅卖出） + 过户费万0.1×2 = 0.102%
3% 网格 → 净 2.90%（费用吃掉 3.4%）
4% 网格 → 净 3.90%（费用吃掉 2.6%）
5% 网格 → 净 4.90%（费用吃掉 2.0%）
```

**3% 是可行的下限**，再往下（比如 2%）费用会吃掉 5% 以上、不划算。中际旭创近 250 日的触发次数：3% 网格 427 次、4% 287 次、5% 201 次（一个「回合」= 买一次 + 卖一次 = 2 次触发）。

### 三种网格基准的对比，以及「当日开盘价基准」为什么在这只票上最好

用户明确说「**追踪网格应该盯着的是当天的开盘价格**」，这个方向是对的。三种基准实测（机动仓空仓起步、上限 4 格约 76 万、间距 4%、含 T+1、成交在触发价，合计 = 已实现 + 期末浮盈亏）：

| 时段 | 区间涨跌 | **当日开盘价基准** | 局部高低点（追踪） | 固定阶梯 |
|---|---|---|---|---|
| 近 250 日 | +401% | **+28.0 万** | +13.0 万 | +0.1 万 |
| 近 120 日 | +70% | **+16.2 万** | +4.6 万 | +2.9 万 |
| 近 60 日 | −11% | **+10.7 万** | −1.7 万 | +9.0 万 |
| 近 30 日 | −24% | **+11.7 万** | −5.9 万 | −6.7 万 |

**读法：看近 30 日那行。这只票跌了 24%，追踪版亏 5.9 万、固定阶梯亏 6.7 万，而当日开盘价基准赚 11.7 万，期末机动仓清零、没有浮亏挂账。**

**为什么它在跌市也能赚**：每天重置基准。今天跌 8%，明天开盘价就是新起点，你在新起点下方 4% 买、上方 4% 卖，不用去追昨天那个已经作废的价位。

**还有一条结构性的好处**：测了三种日内走法（先探低后拉高、先冲高后回落、按收盘方向），**结果一模一样**。因为买单全在开盘价下方、卖单全在上方，两边不交叉，只要当天最高最低确定、成交就确定，**和路径顺序无关**。这说明回测结果不依赖对日内走势的假设。

**读法：国际复材是最关键的反例——它 250 日涨了 615%、是全表涨得最猛的，振幅也最大（7.7%），按直觉应该最适合网格，实际却是全表唯一大亏的。**

**根因：网格的盈亏是不对称的——赚的被封顶在一格 4%，亏的不封顶。**

| | 卖出笔数 | 赚 / 亏笔数 | 单笔均赚 | 单笔均亏 | 合计 |
|---|---|---|---|---|---|
| 中际旭创 | 58 笔 | **48 / 10** | +9042 元 | **−7100 元** | +36.3 万 |
| 国际复材 | 69 笔 | **38 / 31** | +8474 元 | **−14839 元** | −13.8 万 |

**读法：看「单笔均赚」——9042 和 8474，基本相同，因为每笔赚的都是一格约 4% 的钱，谁也多不了。再看「单笔均亏」——7100 对 14839，是两倍多，而且国际复材还多亏了 21 笔。赚的一样多、亏的多两倍还多亏 21 笔，结果就从 +36 万变成 −14 万。**

**至于「涨了 615% 为什么不帮忙」——网格根本没参与那 615%。每笔赚的钱都被卡在 4%，涨得再多也只能拿这么多。**

**亏为什么不封顶**：4 格的买入档位是今开的 −4.0%、−7.8%、−11.5%、−15.1%，**跌到第四格子弹打光，再跌就是裸奔**。两只票被击穿（从局部高点跌破 15.1%）的次数：

| | 击穿次数 | 中位深度 | 最深 | 超 30% |
|---|---|---|---|---|
| 中际旭创 | 7 次 | 23.2% | 44.0% | 1 次 |
| **国际复材** | **11 次** | 17.8% | **55.5%** | **3 次** |

**每次击穿都意味着 4 格货全在手上、而价格还在往下走**——中际旭创击穿后平均还要再跌 9.0 个百分点，国际复材 9.3 个百分点，最惨一次再跌 40.4 个百分点。

### 追踪网格的致命缺陷：在自己买不到货的低点上给高价货定卖出线

**追踪网格的规则是「从局部高点回落 4% 就买、从局部低点反弹 4% 就卖」。这条规则里没有「我的成本是多少」这个变量。**

**实际发生的事**：

```
07-17 价1057  买 @1072   仓位 800股(满)   库存 [1094, 1160, 1116, 1072]
07-17 价 951  ⚠ 触发买入(触发价1029)但机动仓已满 → 买不了
07-20 价1028  卖 @989    配对买价 1072 → 亏 16856 元
```

**在买不到货的那段下跌里，程序仍然在刷新「局部低点」，然后拿这个低点 ×1.04 当卖出线。** 1072 满仓，跌到 951 全程买不了，**但 951 被记成了新的局部低点，卖出线定在 951×1.04 = 989，反弹一到 989 就把 1072 买的货砍了**。同样的模式在 7/28、7/30、8/06 又出现三次。

**举个例子**：你有 4 发子弹，规则是「每跌 4% 打一发」。价格从 1160 一路跌，你在 1160、1116、1072 各打一发，子弹打光。然后价格继续跌到 951，你想买但没子弹了。**问题出在卖的规则——「从最低点反弹 4% 就卖」，而最低点是 951，那是你一股都没买到的位置。951×1.04 = 989，于是价格一反弹到 989，你就把 1072 买的那手按 989 卖了，亏 83 元/股。**

**这不是代码 bug，是规则本身的必然结果。** 固定网格不会有这个问题，因为它的卖出价永远是买入价的 1.04 倍，数学上不可能亏损平仓。

### 波动率聚集：「今天没走满」不预示补涨，预示继续走不动

用户的推断是「中际旭创今天只走了 3 个点，而日均波动 8 个点，所以还有 3-5 个点上升空间」。**前提对了一半，推断不成立。**

**先修正一个数**：这只票过去 10 日的振幅中位数是 **9.76%**，不是 8%（近 10 日实际是 4.1% / 7.5% / 11.8% / 8.3% / 15.2% / 8.9% / 6.5% / 10.6% / 11.7% / 12.5%）。今天已走振幅 3.76%、已走比例 0.39，**「走得少」这个观察完全成立**。

**但历史数据的方向和推断相反**（样本 4974 个股票交易日 / 141 个独立交易日 / 38 只科技股，从 10:30 那根 K 线起算到收盘）：

| 分组 | 样本 | 后续最高 | 再涨 3% 概率 |
|---|---|---|---|
| 全样本（零信号基准） | 4974 | +1.47% | 26% |
| **走得少 <0.45（今天 = 0.39）** | 387 | **+1.23%** | **22%** |
| 中等 0.45~0.70 | 1569 | +1.39% | 24% |
| **走得多 >0.70** | 3018 | **+1.56%** | **27%** |

**读法：走得少那组后续最高只有 +1.23%、再涨 3% 概率 22%，都低于基准；走得多那组反而是 +1.56% 和 27%。上午安静的股票下午继续安静，上午波动大的下午继续波动大。**

**这叫波动率聚集——波动本身有惯性，大波动后面跟大波动、小波动后面跟小波动。它不是一个每天要填满的配额。**

**另外「现价贴着当日最高」也不预测方向**：贴当日最低（<35%）后续最高 +1.48%、贴当日最高（>65%）也差不多，三组都在 +1.44% 到 +1.48% 之间。

### `grain_kind` 与 `kind` 是两个不能合并的字段（umu/prove）

这是今天在 prove 那条线上文档化的核心概念，写进了 `docs/02-ontology/grain-kind-vs-kind.md`。

**为什么不能合并成一个字段——用了实测证据**：物理表 `megrez_exam_submit` 只有**一个** `grain_kind`，却被 **10 条声明**读取，其中 **8 条做聚合**（`kind` 算出来是 `measure`）、**2 条透传**（算出来是 `atomic_dataset`）。**一个 `grain_kind` 对应两种 `kind`，所以必须分开。**

- **`grain_kind`** 描述的是**物理表本身的粒度性质**（一行代表什么），是表的固有属性，26 张表各有一个
- **`kind`** 描述的是**某一条声明用这张表做出了什么形态的东西**（一个数 / 一批可逐行归约的明细 / 一批已压好的行），由 `grain_kind` 加 DSL 形态推导出来，不由人手填

**用银行的类比讲**：`grain_kind` 是「这本账是流水账还是余额表」——流水账一行是一笔交易，余额表一行是一个账户的当前状态，这是账本的固有属性。`kind` 是「你从这本账里算出了什么」——同一本流水账，你可以算出「本月总支出」（一个数），也可以直接把每笔流水列出来（一批明细）。

**落地状态要分清**：`grain_kind` 已实现（commit `1edcdba`），**`kind` 仍是方案、仓库里找不到**。

**spec 同步了一处偏离**：`2026-08-04-registry-taxonomy-spec.md` 的 §2.3 原写三值枚举，实际落地是 **Kimball 四值**。改的原因是逐张核对时发现 `learning_time_aggs_by_id`（学员 × 小时桶）和 `participate_course_detail_bi` 在三值里放哪儿都不对——**它们既不是原始事件、也不是一个实体一行**。四类张数 8/2/6/10 合计 26，与注册表实际一致。

### Docker 容器日志撑满磁盘的处理方式（umu/prove）

**现象**：`csrs-milvus` 的日志文件一天写了 **12G**、没有轮转上限，把 Docker 虚拟磁盘撑到 **23G/24G、可用 0**，导致 `prove-mysql` 挂掉、单测失败、demo 取不到数据。

**处理方式的关键细节**：**用 truncate（`: > 文件`）而不是删除**。因为那个容器还在运行，删文件会让它的写句柄失效；truncate 则让它继续往同一个文件写新日志。清空后 12G/24G、可用 11G，MySQL 起来、140 个单测通过、列校验五项全过（满盘退出没有损坏数据）。

**但这是治标**：日志没有轮转上限，照 12G/天 的速度**两天后会再次撑满**。治本要在 Docker daemon 配置里加：

```json
{ "log-driver": "json-file", "log-opts": { "max-size": "100m", "max-file": "3" } }
```

**代价有两条**：要重启 Docker，会打断 csrs 那边正在跑的容器；而且**这个配置只对新建的容器生效，已有的 `csrs-milvus` 得重建才会应用**。这动的是 csrs 项目的东西，不是 prove 仓库的。

### Slack 定时任务的「跨重启幂等」问题（umu/csrs）

**我今天造成了重复卡片，根因值得记住**：定时任务用**进程内存**记录「今天已跑过」（变量 `_last_run_day`）。为了部署三个修复用了 `--force-recreate` 重建容器，**每次重建这个记录都清零**，而当时东京时间已过 09:00，于是调度器认为「今天还没跑」，又发了一遍。

实际后果：tss-cn 频道今天出现 **3 张卡片**（09:00 正常 + 11:35、12:19 两张重复），tss-co **2 张**（都是 20260806 的），11:35 和 12:19 正好对应两次部署时间。

**教训：任何「每天只跑一次」的定时任务，判重状态不能放进程内存，必须落到进程外（文件或数据库），否则每次部署都会重发。**

## 4. 经验与教训

### 我今天犯的错

**回测有两个严重 bug，都是我自己发现的，但报出过明显不合理的数字才发现。**

**第一个：漏了 T+1。** A 股当天买的当天不能卖。漏了这条之后，追踪网格「近 250 日赚 83.3 万」——**而机动仓本金才 70 万**。

**第二个：让成交发生在当日最高/最低价上，而不是触发价上。** 修完第一个 bug 还是报 82 万，才找到这个。一天振幅 12%，从最低买、最高卖就捕获了 12% 而不是 4%——**这是「事后知道高低点」的作弊**。

**判据值得记住：当回测收益接近或超过本金时，先怀疑自己的模拟，而不是庆祝策略有效。** 修正两个 bug 之后结论完全反了——追踪网格在这只票上大概率亏钱、不是赚钱。

**撤回过三个结论**：

| 结论 | 状态 |
|---|---|
| 「追踪网格越买越贵」 | ❌ **已撤回** —— 单边下跌时两者买价完全相同（都是 917/880/845/811） |
| 「951 不该买」 | ❌ **不成立** —— 951 确实触发了买入，是仓位打满没子弹 |
| 「固定网格亏损配对为 0 所以更好」 | ❌ **已撤回** —— 那个 0 是把亏损藏在了未平仓浮亏里 |
| 「固定网格整体更优」 | ❌ **反了** —— 按已实现加浮动的合计口径，追踪网格在 4 个时段中有 3 个更好 |

**「亏损配对为 0」这个陷阱值得单独记**：固定网格的卖出价永远是买入价的 1.04 倍，所以**已实现的亏损笔数必然是 0**——但那些亏钱的仓位没有卖出、亏损藏在未平仓浮亏里。**只看已实现盈亏会得出完全错误的对比结论，必须用「已实现 + 期末浮盈亏」的合计口径。**

**造成了 Slack 频道的重复卡片**（tss-cn 3 张、tss-co 2 张），根因是定时任务的判重状态放在进程内存里、每次 `--force-recreate` 就清零。**这是设计缺陷不是操作失误，但后果是往用户的线上频道发了重复消息。**

**给了一个错的类比。** 我用「跟着下楼梯的人买」解释追踪网格为什么比固定网格差，用户追问后我验证发现**纯单边下跌时两者买入价完全相同**，类比没解释到真正的差别（真正的差别在卖出侧：固定网格的卖出价与买入价绑定，追踪网格的卖出价与成本无关）。**教训：类比要能被数据验证，不能只是听起来合理。**

**在中际旭创跳水那件事上质疑错了。** 我拿 AAOI「8/6 收盘 −3.38%」去否定媒体说的「夜盘暴涨约 10%」，实际那指的是**电话会后的盘前**（实测 +14.34%）——我把两个时段搞混了。**新浪美股接口里「收盘涨跌」是 `f[2]`、「盘后/盘前涨跌」是 `f[22]`，财报电话会的影响只体现在后者。**

### 今天有效的做法

**做样本外检验，并且如实报告失败。** 网格策略在中际旭创上 +36.3 万，换到国际复材上 −13.8 万。**如果只报中际旭创那个数，用户会以为策略成立。** 而且进一步拆出了失败机制（赚的封顶 4%、亏的不封顶；单笔均亏是 2.1 倍、亏损笔数是 3.1 倍）。

**当结论「太好」时先怀疑自己。** 「近 250 日赚 83.3 万而本金 70 万」这个不合理直接指向了两个 bug。

**主动给「当前有效结论清单」台账。** 这条线上我推翻自己四次，每次都在回复开头列清哪些撤回、哪些成立、哪些还没验证。**这是 8/4 写进 CLAUDE.md 的第一条规则，今天用得最多。**

**批评别人的文档前先确认是不是自己的工具问题。** 时序图在我的文本提取里糊成一行，**查了 HTML 确认是 mermaid 预渲染 SVG、被我的提取工具压平的**，避免了一条错误的批评。

**用 truncate 而不是删除来清空运行中容器的日志。** 容器还持有写句柄，删文件会让它失效。

**处理「三轮问同一只股票」的方式**：中国稀土今天被问了三次，第三次时我给了完整的「三轮下来的当前有效结论清单」，标出哪条要削弱（「按集团归属分组解释力更强」这条在业绩数据出来后要让位给「行业价格驱动」，因为后者能解释四家同涨、前者只能解释两家）。**多轮深挖时用户是跳着看的，每轮都要重新给台账。**

**区分「媒体归因」「官方公告」「市场传闻」三个等级。** 中际旭创跳水那件事，AAOI 是权威媒体归因加三重印证（A+H 同步、AAOI 盘前 +14.34%、媒体两次报道）；中国稀土涨停那件事，半年报是官方公告但时间对不上、行业价格是权威媒体数据、集团重组是官方承诺加市场预期。**每条都要标等级，不能混在一起当结论。**
