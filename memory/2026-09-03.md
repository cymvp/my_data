## 1. 今天获得的知识与技能

### 一阶逻辑的「解释」到底在做什么——今天把这件事彻底讲清了

崔扬对着 `2026-09-02-description-logic-tbox-abox.md` 追问了二十多轮，核心争议集中在「谓词为什么可以映射成一个集合」。这一条值得完整记住，因为它是整套本体理论的地基。

**Tarski 1933 年的定法分两步，顺序不能反：**

**第一步，配对应物（这一步一个字不提「真」）。** 一个解释 I 由论域 Δ 和一张对照表组成。对照表左边是符号、右边是对应物，每个符号只有一个对应物。表分两类行：

- 个体常量 → 对应 Δ 里的**一个元素**
- n 元谓词 → 对应 **Δⁿ 的一个子集**

配哪个元素、哪个子集，**这一步不做任何要求**，由建模的人按现实填。例子：

```
I(张三)     = 张三这个人
I(Teacher)  = {张三}                 Δ 的子集
I(Course)   = {数学课, 语文课}        Δ 的子集
I(teaches)  = {(张三, 数学课)}        Δ×Δ 的子集
```

**到这一步为止，它只是一张表，还没有任何一句话被说成真或假。**

**第二步，定义真。** 归纳定义两条：`P(t₁,…,tₙ)` 为真当且仅当那些项所指的元素组成的元组**落在 I(P) 里**；`∀x.φ` 为真当且仅当把 x 换成 Δ 里任何一个元素 φ 都为真。**「真」这个词在这里第一次出现，它的全部含义就是「落在对照表配的集合里」。**

拿 `Teacher(张三)` 走一遍：查常量行得到张三这个人 → 查谓词行得到 `{张三}` → 张三这个人在这个集合里 → 为真。把谓词行换成 `I(Teacher) = {李四}`，`Teacher(张三)` 变为假。

**这一步是算，不是推。** 「推」是从一些真的话得到另一些真的话，那是更后面的事。

### 崔扬指出的那个循环是真的，我认了并改了

我原来在 2.1 里写「谓词的对应物取集合这个形状，原因是一元谓词的职责是对每个个体给出『是』或『不是』」，然后在 2.2 里用「落在集合里」定义真。**崔扬问：这两句互为解释，先有鸡还是先有蛋？**

**他说得对。** Tarski 的原始定法没有这个循环——第一步只说「配一个 Δⁿ 的子集」，不解释为什么；「职责是回答是或不是」这个说法**提前偷用了第二步的结论来解释第一步**。

**正确的顺序是：配对应物（不提真）→ 定义真 → 走例子 → 事后解释为什么取集合好用。** 「I(Teacher) 恰好等于所有让 Teacher(·) 为真的个体」这个等价**是第二步的后果，不是第一步的定义**。

**取集合的收益在带 ∀ 的句子上**：`∀x. Teacher(x) → Person(x)` 能算，是因为有一个东西叫 `I(Teacher)` 可以逐个遍历。要是把「张三是教师」当成不可再分的基本事实逐句登记，几万句就几万条，而且「所有教师」没有落脚点，带 ∀ 的句子就没法算。

**这条经验可迁移**：解释一个定义时，如果用到了后面才定义的东西，那就是循环。**判断方法是看这个解释里出现的每个词，是不是都在它之前已经被定义过。**

### 「实例关系不由任何谓词表达」这句话我说错了，纠正如下

我原来写「实例关系不由任何谓词表达，由语义规则 2.2 内建」。崔扬很困惑：**实例关系不就是用一元谓词表达的么，比如 `Teacher(张三)`？**

**他的理解对，我那句话省了主语。** 准确的说法是：

- 「张三是教师」这句话**确实由一元谓词作用于常量来表达**，就是 `Teacher(张三)`
- **没有独立符号的是「属于」这个连接本身**——一阶逻辑里不存在 `属于(张三, Teacher)`
- 连接的含义藏在「谓词作用于常量」这个**语法形式**里，由第二步的真值规则给出

### 一元谓词只能表达集合成员关系吗——这是规定不是定理

崔扬问得很锐：「三班有张三、李四两个人，也是一个一元谓词来表达，但并不是实例关系？」

**答案：有理论支撑（Tarski 1933 的语义规则，描述逻辑手册把「实例」直接定义成「个体落在概念的集合里」），但这是一条规定不是定理。**

**崔扬的直觉对应另一种同样合法的规定**：把三班当成**个体**，用二元谓词 `属于(张三, 三班)` 表达。**两种都是合法的一阶逻辑，区别是三班进不进论域。**

### 函数符号与谓词的区别

崔扬问的另一个概念。区别在**返回什么**：

- **谓词**作用在项上，得到的是**公式**（有真假），比如 `Teacher(张三)`
- **函数符号**作用在项上，得到的还是**项**（指一个东西，没有真假），比如 `父亲(张三)` 指一个人

### RDF 比一阶逻辑宽松的两处，以及后果

崔扬问「RDFS + SHACL 是不是合适」，并且直接问了两条限制。答案是**RDF 这两条都不强制**：

| 一阶逻辑的限制 | RDF 的状态 | 例子 |
|---|---|---|
| 谓词的参数位只能填实例 | **不强制**，类可以当主语 | `ex:Teacher rdf:type ex:Occupation` 合法，这正是一阶逻辑禁止的 `职业(教师)`；**RDFS 自己就写 `rdfs:Class rdf:type rdfs:Class`** |
| 只有实例挂属性 | **不强制**，类可以挂业务属性 | `ex:Teacher ex:averageSalary 12000` 合法 |

**元类和 punning（同一个名字既当类又当实例）在 RDF 里是默认状态，不是例外。** 放开的代价：RDFS 层几乎不推理所以没有可判定性问题，**但也没有任何东西阻止把「销售话术」既建成类又建成实例**。

**所以那两条限制要作为我们自己的建模纪律保留，并且用 SHACL 形状写成可校验的规则。**

### `rdfs:domain` 是推理规则不是校验规则——这是个陷阱

**这条是今天最容易踩坑的技术细节。**

写了 `ex:teaches rdfs:domain ex:Teacher`，数据里出现 `ex:c752468 ex:teaches ex:s1`，**RDFS 的结论是推出「c752468 是 Teacher」，而不是报违规。**

要做校验必须用 SHACL 的 `sh:class` 写在属性形状上。**`rbox.yaml` 的 domain、range 导出时要导成 SHACL 形状，导成 `rdfs:domain` 会让校验方向整个反掉。**

### RDF 三元组怎么表达多元语义——给那件事本身造一个节点

崔扬问「RDFS 的三元组能表达用户画像那个多个属性的情况么」。**能。做法是给每一行事实造一个节点，行里每一列变成从这个节点出发的一条三元组。**

**三元组只能表达两个东西之间的一条连线，「多个属性挂在同一件事上」靠的就是让「这件事」自己成为一个节点。**

一行画像大约变成 **10 到 12 条**三元组：

```turtle
ex:f001  rdf:type ex:Fact ; ex:subject ex:learner_张三 ;
         ex:action ex:有属性 ; ex:object ex:职级 ; ex:subProfile ex:role .
ex:v001  rdf:type ex:Version ; ex:ofFact ex:f001 ; ex:value ex:技术经理 ;
         ex:validFrom "2026-08-01"^^xsd:date ; ex:source "自述" ; ex:status ex:active .
ex:技术经理  rdf:type  ex:公司职级体系 .
```

**两张表的结构原样保住**：facts 一行是一个 `ex:Fact` 节点，versions 一行是一个 `ex:Version` 节点，外键 `fact_id` 变成 `ex:ofFact` 那条边。

**但判重键在 RDF 里没有内建的唯一约束**，要用 SHACL-SPARQL 写形状「不存在两个 Fact 节点五个字段的宾语两两相同」。

### 闭世界与开放世界

**闭世界假设**：没记的就是没有。SQL 和 SHACL 都是闭世界。
**开放世界假设**：没记的只是不知道。OWL 推理机是开放世界。

**本公司不采用开放世界**——它和业务直觉冲突（「查不到考试记录」在业务上就是「没有考试记录」）。这也是选型里否掉 OWL 2 DL 的主要理由，而不只是「不需要推理」。

## 4. 经验与教训

### 解释一个定义时，检查它有没有偷用后面才定义的东西

崔扬指出的那个循环是真的：**2.1 用「让它为真的参数组合」定义集合，2.2 又用「落在集合里」定义真。**

**根因是我把「为什么这样定好用」和「这样定是什么」混在了同一节。** Tarski 的原始定法第一步一个字不提「真」，我加的那段「职责是回答是或不是」提前偷用了第二步的结论。

**固化成检查动作**：写完一个定义，把里面出现的每个术语列出来，逐个问「它在这之前被定义过吗」。答不出就是循环，**改法是把解释挪到两条规定都给完之后**。

### 省主语的句子会被读成否定句

我写「实例关系不由任何谓词表达」，崔扬读成了「`Teacher(张三)` 不表达实例关系」，很困惑。

**准确的说法要把主语补全**：「张三是教师」这句话由一元谓词表达；**没有独立符号的是「属于」这个连接本身**。

**固化**：写「X 不由 Y 表达」这类句子时，**必须写清「不由 Y 表达的到底是哪一部分」**——是整句话，还是句子里的某个连接。

### 「这是规定还是定理」要分清，并且要给出另一种合法的规定

崔扬问「一元谓词只能表达集合成员关系，这有理论支撑么」。**正确的回答不是只说「有，Tarski 1933」**，而是要同时说：

1. **有支撑**（Tarski 的语义规则 + 描述逻辑手册的定义）
2. **但这是一条规定不是定理**
3. **你的直觉对应另一种同样合法的规定**（把三班当个体，用二元谓词 `属于(张三, 三班)`）
4. **两种的区别在哪**（三班进不进论域）

**只说第 1 条会让人以为这是唯一可能，而它不是。**

### 推翻自己之前的决定要按流程办，不能只说「现在情况变了」

我提 SHACL，和学员画像「决定一」里明确放弃 SHACL 那句话冲突。**处理方式是：**

1. **先给一份台账**，列出当前有效结论、各自出处、以及我这次要撤回哪几句
2. **说清冲突落在哪一格**——两次讨论针对的是不同的层（存储层 vs 模式层），真正冲突的只有「放弃 SHACL」那一句
3. **说清推翻的理由不在原有触发条件里，是一个新需求**
4. **按流程加一条触发条件并注明范围和日期**，而不是直接改决定

**这个流程比「我认为现在应该用 SHACL」有用得多**，因为它让后来的人能看出这个决定是怎么变的。

### 主动撤回自己上一轮说过的话，并且说清为什么

今天撤回了两条：「scale 列不用再单独存」（那是按三元组存储说的，和决定一冲突）、「学员画像一行写成 Fact+Version 节点」（降级为导出格式，不落库不进 prompt）。

**撤回时要写清原来那句话成立的前提是什么、那个前提为什么不成立。** 只说「我撤回」不够。

把「概念」批量改成「类」时，**误改了两处文件名引用**：


在选型文档的第 223 行和第 299 行，**而且已经 commit 了**（`0f83b22`）。

### `rdfs:domain` 这类「看着像校验其实是推理」的东西要单独标出来

RDFS 的 `rdfs:domain`、`rdfs:range` **是推理规则不是校验规则**。写了它，数据违规时的结果是**推出一个新事实**（「c752468 是 Teacher」），**而不是报错**。

**这类陷阱的共同形状是：一个机制看起来在做 A（拦住错误），实际在做 B（接受错误并改写世界）。** 遇到「声明式约束」时都要问一句：**它违反时的行为是拒绝还是推导？**

### 脚本有副作用时，第一次的输出要留住

昨天为看欠账重跑抓取脚本两次、多下了 7 篇。**今天改了做法：跑一次、输出重定向到文件、后续从文件里读。**
