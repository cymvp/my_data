## 1. 今天获得的知识与技能

**「不重跑」是一条可以直接用的数据纪律。** 今天精读的 arXiv 论文 *Agentic SQL Revisited*（2608.15389，2026-08-15）做了一份十四个系统的排行榜，而它**不重跑任何一个系统**。理由写在论文里：闭源 API 每个月都在变，重跑出来的数字在底座模型一更新的那一刻就漂了，**而漂过的数字看起来仍然像是可比的**。它的规则是「每一个数字格子都追溯到一条引用，不确定的格子留空、而不是靠推断填上」，Spider 2.0 那一整栏因此直接省掉。

这一条对 prove 项目（cuiyang 在优幕做的那个自然语言查询产品，把用户问题编译成对数据仓库的查询并作答）有一笔现成的账：**prove 评测集在 2026-08-17 之前的历史通过率，没有记录当轮用的是哪个模型**——底座是一个路由别名，8/17 查实它当时指向 gpt-5.2，而那之后才把「本次跑见过哪些模型」做成集合落盘。按这篇论文的判据，正确做法不是回头重跑（路由已经变了，做不到），**而是给那些历史数字标上「模型未记录」、让它们不参与跨周比较**。这比假装可比更诚实。这件事目前只是判断，还没落到代码或文档里。

**推理自主度五档，给了一个描述 prove 形态的坐标。** 同一篇论文按「一个系统在问题与最终答案之间外化了多少结构化推理」分档，判据可测：看回答一个问题所用的模型调用的数量与种类。

| 档 | 名称 | 调用形态 |
|---|---|---|
| L0 | 受约束的单轮 | 一次前向传播，带语法级解码约束 |
| L1 | 上下文单轮 | 一次前向传播，只靠提示词里的结构 |
| L1.5 | 推理内化 | 推理时仍是一次调用，但模型被训练成在同一条轨迹内吐出中间阶段 |
| L2 | 迭代精化 | 沿一条固定流水线的多次调用，无动态路由 |
| L3 | 智能体协作 | 多次调用，由控制器在中间产出上分支 |

prove 现在是 **L2**（路由 → 编译 → 执行 → 派生计算 → 对账 → 作答，固定流水线）。此前讨论过的「在路由之前先把能补的 ID 查出来」那个方向会让它往 L3 靠，而论文的第二个发现正好是那个方向的代价：**自主度买到的是稳健性，但要在 token、延迟、编排三方面付账**（这一条论文只给了定性判断，没给倍数）。它的第三个发现给了另一条路——L1.5 把中间步骤压进一次调用、靠训练实现，prove 走不了（不训练模型），但值得知道「把步骤外化成流水线」不是唯一选择。

**精确匹配与执行准确率会反向。** 同一篇的案例研究里，Qwen3-8B 加了思维链监督之后，精确匹配从 47.60 降到 44.67，而执行准确率从 77.04 升到 82.24。原因是精确匹配要求生成的 SQL 与标准答案逐字符一致，执行准确率只要求跑出来的结果一致——**思维链让模型写出更多「结果对但写法不同」的 SQL**。对实际使用来说，执行准确率才是有意义的那个指标。

**用户画像项目的三条已定方法论（今天写进日报的那三条）**：
- **矛盾留在库里，不在入库时消解。** GUMO（一套用户建模本体）明确反对把陈述库变成前后一致的世界模型，消解策略作为**查询的参数**由消费方各自指定。它给的例子是三条关于同一个人棋力的矛盾陈述（一条最新、一条置信度最高、一条本人自述），套五种策略跑出四个不同答案，每个都有道理。对我们的后果：**消解策略不能写死在服务里**——做教学适配时要最可信那条，做学员自述展示时要他自己说的那条，做变化轨迹时要全部。
- **有效期写进维度自己的定义里**，不去找全局稳定性阈值。岗位是年级、「最近在谈一个大客户」是周级、「这次想精学还是略学」是单次会话级。**判断成本从数据量级降到维度数量级。** 过期不删、只降置信度继续可用。这解掉了会上天舒卡住的那个问题（「相对稳定这件事非常微妙」）。2025 年那篇学习者建模综述也独立走到同一处（按时间间隔调整置信度参数）。
- **画像本体只管维度和取值域，世界知识交给别的本体。** GUMO 自己踩过的坑写在论文里：辅助词是「兴趣」或「知识」时，世界上任何东西都能当谓词。对我们就是知识点归课程侧的知识体系，画像只引用不复制，否则每上一门新课都要往画像本体里加概念。配套纪律：**取值域必须来自已有口径或已发表模型，不自己编**——SPOnto 全篇没有一个自造枚举，GUMO 的人格组直接挂了三套现成人格模型。

**另有一条被换掉但仍成立的**（METHONTOLOGY 的开工方式）：本体是为反复复用而建、独立于哪个应用要用它，所以工程师应当**预先把要覆盖的大部分词汇指定出来**；但它同时否定瀑布式、采纳演化原型。合起来是一个分界——**骨架预先定，细节边做边加**。那 25 个字段和维度分组要在动手前定死，具体取值域允许后续增补。它还给了需求规格说明文档的四项必填模板：目的（含谁消费、什么场景）、形式化程度、范围（术语集合与粒度）、知识来源。

## 4. 经验与教训

**为了重看输出而重跑一个有副作用的脚本，是错的。** 今天真栽了：`ontology_digest_fetch.py` 会下载文件并追加台账，我为了看被截断的输出头部又跑了一遍，结果多抓 5 篇、台账多 5 条。**正确做法是把第一次的输出存成文件再分页看**（`… > /tmp/out.txt` 然后 `head`/`sed -n`）。判据：跑之前先问「这个命令改变了什么」，只读的才可以重跑。

**「所有源都没有」不等于「拿不到」——换到权威源去。** 美债那题前三个免费源全空，第四个是美国财政部官方的每日收益率曲线 CSV，一次拿到全期限真值。免费聚合源覆盖不到的东西，一手发布方通常有。

**同一件事「按 skill 字面执行」与「按已知约束执行」冲突时，停下来问，不要自己选。** sync skill 写的是 `git add -A`，而 my_data 是公开仓库、里面躺着在审专利的答复策略。照字面执行会公开发布法律材料。今天的处理是把其余部分做完、把这一处单独拎出来问，这个做法应当保留：**先把不依赖答案的都做完，只在真正需要决定的那一处停。**

**「三个选项里没人选的那个」是一种可识别的错误形状。** 那两个 `loop_tasks.json.bak*` 文件，待决选项是「删掉」和「gitignore」，而 `git add -A` 会选出第三种（提交进公开仓库）。**当一个默认动作的结果不在任何一个候选方案里时，那个默认动作八成是错的。**

**给用户写心得体会时，不要写成失误总结。** 今天第一版被明确纠正：要的是「这次调研获得的、可以用于项目的收获和经验」，不是「我犯了什么错」。教训类的内容可以占三条里的一条（作为方法教训），但不能是主轴。

**二手转述会把一份工作说得比实际扎实，动手之前先确认手里这份是不是全本。** 这条是前几天的教训，今天写进了日报：按 SPOnto 论文的转述判定另一篇 2017 年的工作「建模了已遗忘的知识和误解」并排在追读第一位，核对后发现那篇只提了一句间隔重复算法、作者自己还承认「遗忘在相关方法中几乎没有被处理」。同类还栽过一次：拿一篇 4 页会议论文做了完整摘译，后来发现它只占同一作者那本 288 页专著的 2%，据此写下的「这篇没写冲突消解」完全站不住——书里专门有 22 页讲这件事。

**产物自检要看比例而不是看绝对值。** 今天三篇精读的「抽出字符 ÷ 源 md 字节数」都落在 0.51–0.54。**比例一致才是「渲染正常」的证据**；单看某一篇「抽出 10956 字符」看不出好坏（中文在 UTF-8 里一个字三字节，所以字节数天然大于字符数）。8/20 栽过的那次是无头 Chrome 拿不到系统中文字体、产出页数正确内容全空的 PDF、退出码还是 0，所以这个数字必须看。

**定时任务错时触发时，要按任务性质区别处理。** 今天 ycui_sync 在 09:07 BJT 被触发（目标 20:00 BJT），我直接跑了——因为同步是幂等的、跑早了无害。**但每日 memory 生成和 Slack 发送不是**：memory 早跑会用半天的数据覆盖整天的文件，Slack 早发会重复推送。这个区分要在每次错时触发时先做一遍。
