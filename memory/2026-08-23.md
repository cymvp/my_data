显隐性也跟着反转：初始化显式 34、隐式 10；运行期隐式 49、显式 6。**主流做法是「冷启动直接问学员，跑起来之后靠系统观察」。** 会上定的「开课前先问精学还是略学，之后从对话抽取」正好是这个做法，183 篇的分布说明它不是临时主意。**但推论是：这两条路径的数据源、可信度、更新频率都该分开声明，不要合成一套。**

**② 掌握度为 0 分不清「没学过」和「忘了」**（Wang 等 2021）。这一句给了「遗忘不能归零」一个实际理由而非理论偏好——**两种状态的教法完全不同，一个要复习，一个要从头教**。而贝叶斯知识追踪（BKT，一种按答题序列估计掌握概率的经典方法）的做法恰恰是直接归零。

另外三条遗忘相关的新发现：**Martynov 2023 区分「知识的遗忘」与「技能的丧失」**——知识是会忘的，技能是不练就退化的，企业培训里两者干预方式不同；**Hansen 2017 关心认证的续期**，而**合规培训年检本质上就是「假定一年后知识已衰减到需要重新确认」**，这给遗忘机制在企业场景里找到一个不需要说服任何人的业务落点；**Qinghong 2015 用遗忘因子加半衰期**，半衰期是连续量而 GUMO 的 `durability` 是定性档位（分钟／小时／天／年），两者可以并存——档位定量级，半衰期定曲线。

**③ 处理误解的只有 4 篇（2%），比遗忘还稀缺。** 四篇里 **Abyaa 2017 是唯一同时用本体、用扰动模型、又答遗忘那个研究问题的，而且领域是成人学习**。这修正了之前对这篇的两次误判：先按 SPOnto 的转述排第一顺位，又因综述说它「只提到间隔重复算法」而降级——**现在看，该追它的理由不在遗忘，在于它是唯一一篇把本体和误解建模接在一起的**。

**两个统计背景**：本体在实际使用中排第四、占 12%（预测建模 56 篇、不确定性建模 32、分类 24、本体 22），与综述正文把本体降格为「一种结构化的用户表示」一致；**企业培训场景几乎空白**——113 篇未指明领域、46 篇高等教育、14 篇中小学，**成人学习加职业培训加终身学习总共只有 9 篇、占 5%**。这意味着这个领域的成果绝大多数围绕在校学生做的，迁移到企业要自己判断；同时空白本身是机会。

**还有一条方法论数据支撑了「组合使用是常态」这个判断**：那篇综述里有记录建模方法的 102 篇论文中，**64% 同时用两种以上方法，只用一种的占 36%**。

### 九种学习者建模方法，以及我们实际在用哪些

这一节是今天被 cuiyang 追问后才理清的，价值很高，因为它把「本体」放回了它该在的位置。

| 方法 | 一句话说它干什么 | 用它的前提 |
|---|---|---|
| 覆盖模型 | 先有一份完整的领域知识树，学员的知识是它的子集，学过的打勾 | 必须先有知识树 |
| 扰动模型 | 覆盖模型加一件事：不只记「没学」，还记「学错了」 | 先有覆盖模型 |
| 本体 | 把「有哪些字段、每个字段能填什么」写成一份正本，所有程序照它读写 | 需要有人把字段和取值定下来 |
| 不确定性建模 | 用概率或模糊逻辑表示「大概会、七成会」 | 需要一批数据估参数 |
| 基于约束的建模 | 事先写一批不能违反的规则，违反哪条说明哪里理解错了 | 领域里得有可判定的对错 |
| 分类（有监督） | 把学员归入若干预先定好的典型类型 | 需要先有类型体系 |
| 聚类（无监督） | 让算法从数据里自己分堆，分完再起名 | 需要一批真实数据 |
| 预测建模 | 算出一个数：他下一题会不会做对 | 需要可反复观测的答对答错序列 |
| 认知理论 | 借用心理学或教育学已有的框架来刻画学习过程 | 需要选一个合适的理论 |

**我们已经在用三种，此前没说清**：

- **覆盖模型——已经在用。** PM 那份提示词里有一句「不是某个具体知识点达到了什么层级（那是**状态判定器**逐轮记录的事，这里不出现 kp_id）」——那个状态判定器就是覆盖模型，而前提（课程本身有知识点树）我们满足。
- **本体——已经在用，但很轻。** 五个字段、每个字段固定取值、正文是自由文本。
- **认知理论——今天刚用上。** 学情两档绑到布鲁姆刻度上。

**所以真实分工是：画像这一层用轻量本体加认知理论，知识点那一层用覆盖模型。** 这也解释了提示词里为什么专门划一句「学情里不出现知识点标识」——那是在划这两层的界。

**要加两种**：**扰动模型**（补「误解」缺口，门槛特别低因为唯一前提是已有覆盖模型；要动的是状态判定器不是画像抽取器，所以可独立排期）、**分类**（治冷启动，但类型划分必须由教法数量倒推）。

**不用四种**：不确定性建模（毁掉可审计性，而审计是会上的硬要求）、基于约束（软技能没有可判定的对错，前提不满足）、聚类（要等数据，是本体的下游而非替代）、预测建模里的 BKT（**输入不存在——对话拿不到答对答错序列**）。

**本体在这里不可替代的只有一件事**：把字段清单和取值范围定成一份正本，让三个程序照同一份读写。替代方案是三方各自理解，后果是抽取器输出「基本掌握」、教学决策按「已有基础」判断，**两边都以为自己没错**。

### 美债：不寻常的不是数字，是组合

**全部来自美国财政部官方 API，可复核。**

10 年期收益率 4.74% 放进 1985 年以来 501 个月的历史里只是**第 57 分位**（中位数 4.42%）。年代均值：1980s 8.76%、1990s 6.65%、2000s 4.42%、**2010s 只有 2.37%**、2020s 3.12%。**真正反常的是过去十年——我们把那十年的极低利率当成了「正常」。**

**真正站在历史极端的是长端**：30 年期 5.27%（有报道说本周一度触及 5.33%、19 年来最高），而 20 年期 5.25% 比 10 年期 4.74% 高出 51 个基点，曲线在长端明显陡峭。

**债务负担**：联邦债务总额 **40.03 万亿美元**（2026-08-20），其中公众持有 32.28 万亿、政府内部持有 7.75 万亿。本财年前 10 个月（2025 年 10 月至 2026 年 7 月）：财政收入 4.485 万亿、支出 6.284 万亿（占收入 140%）、赤字 1.799 万亿（40%）、**利息支出 1.170 万亿（占收入 26%）**。

三个换算帮建立量感：**每收 100 块税，26 块用来付利息**；每花 100 块只有 71 块有税收对应、29 块靠借；**利息支出约是国防预算的 1.5 倍**。

**这件事最硬的部分**：加权平均票息只有 3.51%，而新发债要按 4%~5% 定价——**老债到期换新债，利息还会继续往上走，即使利率不再涨。**

**「美国要崩溃」这个判断的处理**：美债是用美元计价的，而美元是美国自己印的——一个国家借自己能印的钱在技术上不会「还不上」，真正的约束是通胀和汇率，不是违约。而且需求还在（上周财政部宣布把国债回购规模至少扩大一倍，收益率就从多年高点回落了一些）。但 26% 这个比例是真问题，它是**慢性挤出**而不是「哪天突然崩」。1990 年代收益率 6.65% 时美国债务只有 5 万亿左右，**现在利率一半、债务八倍**——这才是不寻常的地方。

### 本体论精读今天读到的两条

**一，把本体知识编译进图查询**（CIKM 2026，arXiv 2608.20092）。核心是「物化」与「查询改写」两条路的分岔：物化把本体能推出的隐含事实都算进库里（库膨胀、本体一改全部重算）；查询改写**库不动，把本体推理编译进查询本身**。这篇做的是「纯改写」——本体推理完全编译进查询、不需要数据预处理、可直接交给现成引擎。**它卡了十多年是因为两个障碍，而 GQL/SQL-PGQ 的 ISO 标准化一次性移除了两个**（实用图查询语言此前只部分支持正则路径查询；而已证明最简单的 DL-Lite 本体下普通正则路径查询也改写不成合取形式、必须用嵌套）。

**这篇最有用的一条对照是「改写快、执行慢」**：改写在 250 毫秒内完成（DBPedia），而 100 条查询里 **56 条执行超时**。论文自己承认优化执行不在范围内。**prove 项目在结构上就是「查询改写」那一路**（把指标口径展开进查询，而不是为每个口径预算一张物化表），所以这个失衡是这条路的固有形状——**如果口径复杂的查询特别慢，第一反应不该是怀疑编译器，而是先问改写后的查询形状是否触发了执行引擎的坏路径**。

**二，给写代码的 agent 一份有类型的项目记忆**（NeSy 2026，arXiv 2608.13662）。它主动否掉了自己的卖点——知识图谱在**检索精度**上只比向量记忆领先一个恒定小幅（50 到 634 条的规模研究里斜率置信区间跨过零），论文写「检索精度不是区分点，单靠它大概不足以证明这个系统的正当性」。**它真正的主张是三类问题 top-k 检索按形状就答不了**：有多少个（1.00 对 0.18）、有没有（0.98 对 0.06）、顺着取代链走到哪（0.98 对 0.27）。**而原因不是摄入不全——向量库里有那些事实，只是检索一次只交出排序后的一个切片。**

**三，GQL 的 GRAPH TYPE 与 RDF/SHACL**（Neo4j 开发者博客，作者是 GraphAware 的 CTO，立场明确）。它把三件常被混为一谈的事分清了：**RDFS/OWL 回答「还有什么必然为真」（推断）、SHACL 回答「跑检查时这张图合规吗」（校验）、GRAPH TYPE 回答「每次写入时这个库允许装什么」（引擎原生的不变量）**。它最锋利的一句是「RDFS 和 OWL 是为推断而造的，我需要的是为拒绝而造的东西，这是相反的两件工作」。

## 4. 经验与教训

**用 `-s` 把 curl 的错误藏起来，会让「网络中断」看起来像「服务器限制」。** 那个 79.7 MB 的包，第一次判断成「服务器在 38 MB 处截断」是错的：curl 实际报了 `(18) transfer closed with N bytes remaining`、退出码 18，**但我只看了 `http_code` 和 `size_download`**。判据是：**`Content-Length` 给的是完整大小，就说明服务器打算发全量，断了是网络问题、值得重试。** 后来第五次就下全了。**下次用 curl 下大文件，要看退出码，不要只看 http_code。**

**「本体设计」这个文件名名不副实，是一处该认的偏差。** 那份文档里真正属于本体的只有两节（一条记录有哪些列、五个字段各自记什么），其余分别是认知理论的轻量应用（布鲁姆刻度）、普通软件工程（状态机）、数据治理（来源字段）、测试设计。**已改名为「学员画像设计」。教训是：给文档命名时，先数一下里面各节实际属于哪一类工作。**

**「第一版先不拆，等有第二条数据来路再说」这个理由站不住，而且它踩在自己写进文档的那条教训上**（改字段语义要当成数据迁移来排期，因为历史数据不会自动重算）。两句错都要记：**一，「难度」判断反了**——让模型输出四个受约束的键比让它写一句自由文本**更容易**，因为约束越多、可选空间越小；而且 PM 自己在两个字段上已经半拆开了，**说明结构是自然的、不是我们强加的**。**二，把好处只算成「跨来源比较」是算错了账**——真正的好处是让判重与判方向从「大模型的判断题」变成「键匹配加刻度比较」。

**被批评「上来就是细节，缺总体设计」之后的正确改法是补两节前置，不是重排细节。** 具体做法：第一节一句话说清这是什么（**这是一张表，一行是一条关于某个学员的结论**，它处于中间层、一头连教学对话一头连教学决策、自己不做决策只存结论）；第二节画出六步循环；**然后每个后续小节开头补一句「它作用在第几步」，末尾给一张对照表**。这样读到「四种状态」那节时立刻知道它是写入服务在第五步干的事。**副产品是发现了「五个待定问题全部落在第一步」这个此前埋在细节里看不出来的事实。**

**「记忆服务宕了而 agent 静默地去 grep 原始文件」是一个要主动防的失败形状。** 这是今天读的那篇 agent 项目记忆论文里的教训，而**昨天刚栽过同型的错**（一个 `NameError` 被裸 `except Exception` 吞掉，症状只表现为「取数失败」，查了三轮）。**论文给的解法比「在 except 里加日志」更进一步：主动核实那个组件真的被调用了，而不是等它报错。** 这一条对每日 memory 流水线直接适用——`extract_sessions.py` 如果某天少扫一个 session，产出看起来完全正常、只是薄一点，**应该核实「本次扫到几个 session」这个数字**。

**问「这个东西要不要公开」之前，先查同一个目录里已经公开了什么。** 昨天把 `专利/OA2答复/` 拎出来问，理由是仓库公开——**但只看了 `git status`，没查这个目录已跟踪了什么**。实际上 `OA1答复/` 早就在里面了。**判据：`git status` 只告诉你没跟踪的，`git ls-files` 才告诉你已跟踪的，而后者决定这个问题的性质。** 问错了依据，就算结论碰巧相同也是运气。

**批处理式的检查治不了积压复利，节流要放在上游。** 本体论流水线的欠账检查是典型的「跑一次检查，告诉你什么已经坏了」——它在第二天早上告诉我昨天欠了几篇，而不是在昨天阻止我漏做。**但这个位置未必错**：「让漏做不可能」在一条依赖人逐篇通读生成的流水线上没有意义，没有引擎能拒绝「我今天只做了三篇」这次提交。**所以正确的启示不是把它改成闸门，而是承认它是批处理检查、于是它的失败模式（积压复利）必须靠上游节流控制。** 具体建议是把每日抓取篇数从 5 降到 2，还没获批。

**「由应用保证 schema」这类前提会随规模自己失效，而失效不需要任何人做错事。** 这是今天读的 GRAPH TYPE 那篇里最通用的一条观察。判据：**问一句「这个保证依赖什么前提，那个前提会不会随规模自己失效」**；会失效的，就得把保证下移到所有参与方唯一共享的那一层。**手上有一处同形**：「webhook 不写进公开仓库」这条纪律现在靠「我每次提交前 grep 一遍」执行，只有一个执行者时有效。webhook 文件放在仓库外（`~/.slack_webhook_url`）这一半已经做对了，**差的是一个 pre-commit hook**。

**回答「财报出来第二天怎么走」这类问题，先核实前提。** 今天查中际旭创公告，巨潮（cninfo）接口对 300308 一直返回 0 条，而同一接口前天查 000831 是好的——**大概率是参数不对或限流，不是真的没有公告**。换新浪的接口交叉验证，确认半年报是 8 月 22 日（周六）披露的。**「前提不成立的话后面整套分析都是空的」，所以核实要放在最前面。** 另外两个样本（新易盛、天孚通信）比 2019 年的老数据更有参考价值，但**两个样本说明不了什么**——所以才转向自有的 38 只票三年数据做分档统计。

**用真实行情核对新闻转述，不要只信转述。** 今天查同行半年报反应时，新闻里的说法与实际行情对不上，核过之后两个事件的形态**正好相反**。

**涉及「某个具体的人说过什么」，先去核原话再答。** 今天那个美债问题里混了三样东西：一个可查的事实（收益率）、一个流传的判断（美国要崩溃）、一句归到特朗普名下的话（靠战争减缓债务）。**第三样核出来是转述失真的**——他说的是「用美军干预债市」，不是「靠战争减缓债务」，而且原话是 8 月 21 日说的。**把三样分开处理、并明说它们可信程度差很远，是这类问题的正确处理方式。**
