## 1. 今天获得的知识与技能

- **复合键 join（做考试域的硬需求）**：考试域跨表关联必须用 `session_id + exam_submit_id` 双键，单键会把不同考试的记录串在一起。prove 的 DSL 编译器为此扩展支持复合键 join；且复合键里的"分片列由参数固定、行键才是真正连接键"要分开处理。
- **注入防线与 DSL 白名单的取舍**：prove 的表达式白名单（防 SQL 注入）默认不含比较符和 JSON 函数。今天为"条件计数"给 DSL 加了受控的 `count_if` measure（编译成 `SUM(CASE WHEN…)`，条件复用 where 的同一套校验），而不是放开白名单；满分需要解析题目 JSON、JSON 函数会引入引号破坏 token 防线，所以坚持不加、把该指标登记为"暂不可出数"并记 TODO。这是"宁可少一个指标，不破注入防线"的纪律。
- **MyCat 的两个限制**（JP 数据通道踩到）：① 不接受库名限定的表引用（`db.table`），因 channel 已限定同库 join 所以库名多余，去掉即可；② 不支持 `AVG()`——改成 `sum/count`（页面 SQL 本来就是这么写的）。
- **`is_achived` 字段的真实语义**（考试提交表 megrez_exam_submit）：`is_achived=0` 不是"未完成"，而是"每人保留的最新一次提交"（历史提交标记为 1）。这个语义直接推翻了设计文档里"陷阱一"的初判——**字段语义必须打真实数据查证，不能望文生义**。
- **`vlt_max` 口径分歧**：PHP 业务侧 `Vlt.php:99` 把 `vlt_max=0` 当"未设置、返回原值"，但 Doris 查询 SQL 只判 `isnull` 不判 0；三门测试课 vlt_max 都是 0，两种算法结果不同。这类"业务代码口径 vs 数仓 SQL 口径"的分歧要以业务代码为准并在指标里对齐。
- **Claude Code 桌面版远端目录**：「Browse remote folder」灰掉是因为工作目录在开会话前选定、运行中不能换；换目录要开新会话选，或改本机 `~/.claude/settings.json` 的 `sshConfigs[].startDirectory`；`/add-dir` 可追加目录，没有 `/cwd` 命令。

## 4. 经验与教训

- **字段语义必须打真实数据查证，不能望文生义**：`is_achived=0` 想当然以为"未完成"，实为"每人最新一次提交"，直接推翻了 Spec 的核心结论。发现自己错了立即改指标 + 纠文档，不掩饰。
