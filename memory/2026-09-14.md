## 1. 今天获得的知识与技能

### 批量判定掉准确率，文献里有直接实验；但「注意力稀释」这个解释没有文献支撑

这是今天最干净的一次「把自己的推测和已验证的事实分开」。

用户问：spec 里那套「两步/两遍判定法」解决注意力稀释，有理论基础吗？核查结论是**有支撑，但支撑的位置和 spec 写的不完全重合**：

- **文献直接支持的**：一次调用里塞进多条独立判定，准确率会随条数上升而下降。论文是 *Batch Prompting: Efficient Inference with Large Language Model APIs*，10 个数据集实测，原文结论是「批量大小增到 6 时，5 个数据集里有 4 个出现显著下降」，推荐值落在 3 到 4。
- **文献也支持的**：把一个大判定拆成「先定位、再逐条核」两步，在事实核查领域有正式名字——**Decompose-Then-Verify**（先拆解、再逐条核验）。代表工作是约翰霍普金斯的 CORE 论文，其摘要直接用了这个词组，说明它是该领域约定俗成的框架名。
- **文献不支持的**：「每条分到的注意力被稀释」这个**机制解释**。这个说法在文献里没有对应的公认机制名。**实测数据只证明了「批量条数」和「漏判率」同向变化，没有证明原因是注意力。**

把参数摆在一起看很说明问题：

| 来源 | 单次调用判几条 | 准确率变化 |
|---|---|---|
| 论文观察到的拐点 | 6 | 5 个数据集里 4 个显著下降 |
| 论文推荐值 | 3–4 | 与逐条判定持平 |
| 我的 LL eval 第二版 | **16** | 漏判率 3% 升到 40% |

16 条是拐点的 2.7 倍，出现 37 个百分点的劣化在数量级上是合理的，不是异常值。

**还有一条判断值得记住**：spec 里那组隔离实验（窗口固定不动、判定条数从 16 改回 1、漏判率 40% 降到 3%）**本身就比任何一篇论文更有说服力**，因为它跑在这个任务、这本书、这个判官上。**文献的作用是说明这个结果不是偶然，不是用来替代它。**

同一篇论文还写了：批量的效果受**任务复杂度**影响——简单任务上批量几乎无损，复杂任务上劣化明显。而 spec 的分工正好按这条切：粗筛判「这个窗口与这条知识点相关吗」属简单任务，可以 16 条一批；细判判「这条正文能由这段原文推出到什么程度」属复杂任务，必须一条一判。**这两个方向是同一条规律的两种应用，不是两套道理。**

### 术语不一致有三层，最危险的是第三层

今天把设计文档的术语问题分成三类逐层扫，严重程度递增：

**第一层，前向引用**：术语在定义之前就被使用。扫出 **22 个**。改法是把定义集中到术语表——原来术语表只有九个配置对象（场景、环节、关键信息、语义点这些），补了一组方法用词十四条（判据、准入、叶子、父组、池、金标、双标、裁定、初标、交叉复核、归并、簇、复制血缘、示范语料，外加标注者是谁）。改完只剩九个词还在术语表之前，全在开头总览页——总览的性质就是先给结论，躲不开，所以加了一句提示。

**第二层，同一个东西几个名字**：
- 站点名中英混用十三处（CN / JP / CN 站 / JP 站）→ 统一为「中国站 / 日本站」
- 标注者有四种叫法（两会话 / 标注会话 / A 稿 / B 稿），**同一段里能同时出现「两会话」和「A 稿」** → 统一为「两个标注者 / 第一个标注者 / 第二个标注者」
- 更严重的一处是用户直接点出来的：技能行为、通用行为、技能节点、行为节点——**四个名字指同一个东西** → 统一为「**技能点**」，和「知识点」对称

**第三层，同一个词指不同东西——这层最危险，因为读者不会察觉**：

「权重」在文档里同时指三个层级的量：

| 层级 | 含义 | 实际情况 |
|---|---|---|
| 环节权重 | 这个环节占总分多少 | 作者会认真配，开场 15、信息传递 25 |
| 要点权重 | 环节内某条评分要点的分量 | 有用 |
| 条目权重 | 某条关键信息或异议的分量 | **两站源数据里全是 1，作者从没用过** |

三者混在一个「权重」里，读者看到「权重 25」不知道是哪一层。现在术语表列三层对照，正文十七处一律带限定词。

还有一处撞名：技能点里有个叫「证据引用」的（学员引用研究数据支撑论点），和讲掌握度时说的「证据」完全是两回事，已加注区分。

### 「分界线对齐」和「命名对齐」是两件事

原书除了 13 章还有一层 PART 分层（正文页 35、102、221 三处分隔页）。把拆出来的 5 个分组和这一层对起来：**五条分界线全部落在原书的 PART 边界上，没有一条横跨。**

所以分组在**结构上**是对齐原书的。**真正丢掉的是命名**：原书的 PART 名字构成一条时间主线（开口之前该做什么 → 怎么开口 → 怎么收尾），而拆出来的五个名字是五个话题名，**学员从目录上看不出这条主线**。

### 归并只做了精确同文匹配，这是当前最影响掌握度可用性的缺口

用户问有没有做知识点的聚类与相似性合并。查脚本发现**只有一件事：把文本去掉标点空格后比字符串是否完全相等**。没有编辑距离，没有向量相似度，没有模型判等价。

现算的后果：

| 检查项 | 数量 |
|---|---|
| 同企业内完全同文却没归并 | 14 组 |
| 同企业内相似度超 0.85、明显是同一条 | 68 对 |
| 标注者在备注里标了「同一事实」 | 92 条 |

**后果很直接**：两条讲同一件事、只差几个字的表述现在是两个独立节点，掌握度会当成两件要分别掌握的事——学员讲了其中一种说法，另一个节点记 0。而那 92 条是标注者边标边发现的，**没有系统扫过全池**。

### 产品侧对评分要点只校验非空，但提示词里假设了它是动作或态度

用户追问企业为什么可以自定义开放的评分要点类型。查产品实情：**只有一条校验——非空**。没有类型字段、没有模板、没有长度上限、没有条数上限。作者甚至可以在这段自由文本里另写一套自己的评分档位让模型读出来。

**但产品并非没有预期**：默认五档评分写在提示词里，档位定义的原文是「要求的**动作或态度**完全没做」。也就是说产品假设作者写的是动作或态度，只是不强制。

**所以真正的风险不是漏了第八类，是错配。** 三家 386 条里有 36 条既不是动作也不是态度（21 条覆盖类、9 条通用类、6 条指向类），而产品拿「动作做没做」的五档去评它们。之前那次误评就是这么来的——一条写给残肾异议的内容型要点被套到价格异议上判分，**模型自己在评语里写「此处为误评维度」**。

## 3. 工作环境 / 公司 / 业务背景

### 医药知识技能图谱的术语正本（今天确立的）

**统一后的两个核心名词**：**知识点**（原「知识叶子」）与**技能点**（原有四个名字：技能行为、通用行为、技能节点、行为节点）。两者对称。

**「权重」必须带限定词**，它有三层：环节权重（占总分多少，作者会认真配）、要点权重（环节内某条评分要点的分量）、条目权重（某条关键信息或异议的分量，**两站源数据里全是 1，作者从没用过**）。

**站点叫「中国站 / 日本站」**，不用 CN / JP。**标注者叫「第一个标注者 / 第二个标注者」**，不用 A 稿 / B 稿 / 两会话。

**术语表现在有两组**：九个配置对象（场景、环节、关键信息、语义点等）+ 十四条方法用词（判据、准入、叶子、父组、池、金标、双标、裁定、初标、交叉复核、归并、簇、复制血缘、示范语料）。

### 金标验的是判据，不是数据

做法：抽 200 条，两人独立标，算一致率，分歧逐条裁定，改判据，**改完才批量标剩下的九百多条**。

关键认识：**判据是一句句中文规则，写的人觉得明白，换个执行者可能理解成另一回事。一致率低不代表数据难标，代表规则有歧义。**

## 4. 经验与教训

### 用户今天的纠正，按主题归类

**主题一：只写最终采纳的方案，不留中间的错误方案。**

> 「你只需要写出最终采纳的方案就行了，中间那种错误方案不需要留在文档里。」

这是一条文档原则，所以我扫了全文，这类「纠错叙事」一共**六处**：热词的性质、行为名一致率、关系分三类、七类的出处、证据的提示条件，加上用户指的字段拆分。全部改成只写结论和依据，**修订史留在 git 里**。

**沉淀**：设计文档记录的是当前的设计，不是设计的演化史。「我原来以为 X，后来发现是 Y」这种句式在 spec 里一律改成直接写 Y。

**主题二：同一个东西不要起两个名字。**

> 「行为和 skill 的区别是什么？如果是一个事情，你不要起两个名字！」

实际起了四个（技能行为、通用行为、技能节点、行为节点）。这条促成了全文三层术语扫查，也扫出了更危险的第三层（一个词指三个不同的量）。

**主题三：前后矛盾要当成逻辑问题查，不是措辞问题。**

> 「『技能不只来自评分要点』这一节的描述前后矛盾啊！到底技能能不能来自评分要点之外的地方？」

用户直接引了自相矛盾的两句。**这类问题不能靠改措辞解决，得回去想清楚设计到底是什么。**

**主题四：术语引用要前后一致。**

> 「『每个语义点过一遍准入和分类判据』==> 什么是准入和分类判据？**你要保证名词/术语引用的前后一致性和连贯性！**」

这一处被处理成自解释的句子：「每个语义点先判准入，也就是够不够格建成知识节点，再判分类，也就是属于哪个知识域、哪种知识类型」。

**主题五：报告不要列不必要的数字表格。**

用户给了六个章节标题并逐章指示，其中一条是：

> 「这一章不需要列数字表格和数字了，只是叙述一下考虑角度」

**沉淀**：不是所有结论都需要数据支撑到表格级。当这一章要说的是「考虑角度」而不是「量化结论」时，表格是噪声。

**主题六：文档标题里不要重复同一个词。**

> 「『拆书』重复了两次，收一下。」

改的时候发现直接替换会变成「拆书产物的拆书体验性问题」，所以把「产物的」一起去掉了。

**主题七：按知识点统计，不是按章节统计。**

> 「我让你按照知识点来统计，不是按照章节统计。」

同一批数据有两种聚合方向，**方向选错了答的就不是用户问的那个问题**。

**主题八：追问方法本身。**

> 「你这个是怎么做的统计，为什么这么快？」
>
> 「如果一个知识点有 3 句话，分散在 3 个 chunk 里，那你是如何判断某块是这个知识点的来源的？」

**这类追问最有价值**，因为它检验的是方法而不是结论。一个快得可疑的统计，往往是因为口径被悄悄简化了。

### 今天自己犯的错，按形状归类

**形状一：写了一个没核过的出处。**

我在昨天的提交里写了「七类的正本在分类框架 v0.3」。今天去查证，**那份文档里根本没有这七类**。这句话是顺手写的，没核。

而查证的链条也值得记：先查分类框架（没有）→ 查修订清单（写着「归构建方案与打标 SOP 维护」）→ 查那份 SOP（**从来没建过**）→ 查 git 历史找七类最早出现在哪 → 确认真实来历是试点归纳。

**沉淀：凡是写「X 的正本在 Y」，必须打开 Y 确认。** 这类句子的错误成本很高，因为后来的人会照着它去找。

**形状二：拿一个自己也有问题的东西当正面对照。**

写报告时用第 7 章当「篇幅与条数相称」的正面对照，但**那一章自己的两条知识点正是四对部分重叠里的一对**。对照组必须先验证自己是干净的。

**形状三：把推测当成机制写进 spec。**

spec 里写「每条分到的注意力被稀释」。实测数据只证明了**批量条数和漏判率同向变化**，没有证明原因是注意力。文献里也没有这个机制的公认名字。

**沉淀：现象和机制要分开写。** 「A 和 B 同向变化」是观测，「因为 C 所以 A 影响 B」是解释——后者没有证据支撑时，要么标成推测，要么不写。

**形状四：口径没说清就给结论。**

「重要」有两种口径（按书的分量 vs 按教学判断），它们会打架，而其中一种我量不了。**在给出「这几条可有可无」这个结论之前，必须先说清用的是哪个口径**，否则结论会被误读成「拆书抽错了」，而实际情况是「它按书的结构抽，而这门课不想按书的结构教」——**两者的处置完全不同**。

### 今天有效的做法

- **查依赖关系要分两层**：先查「声明的依赖」（字段），再查「实际使用」（正文里有没有真用到）。只查前者会把标错的依赖当成真的——今天就是这样查出 `deps` 字段不可靠的。
- **从原文里挖依据，不靠读后印象**。要一张章节依赖图时，去原书正文抽作者自己写的路线图和显式回指，七处每处带页码。**这样的图，关系不是我推测的，是原文直接说的。**
- **用「书自己的口径」量重要性**：章末要点框（作者自己写的「本章要记住什么」）+ 核心术语出现次数。两个都不是我的判断。
- **机械信号一对都没命中，本身就是发现**。做重叠分析时字面重叠零命中，这说明重复是语义层面的、改写过的，不是复制粘贴。
- **主动给证据打折**。七类外推验证做了 780 条零例外，但同时写明：只来自 6 家企业，且**两批的标注者是同一批**，遇到难归的条目可能往最近的类里塞而不提新类，**这种偏差自己发现不了**。
- **文献的作用是佐证不是替代**。手上那组隔离实验跑在真实任务、真实数据、真实判官上，比任何论文都更有说服力；文献用来说明这个结果不是偶然。
