- **优先级**:`P0 红线`(安全/数据正确性,且是其他能力上线的前置闸)> `高` > `中` > `低`。
- **工作量**:`大 L`(跨多模块、数周以上)/ `中 M` / `小 S`(局部、数天)。
- **状态**:`进行中` / `待部署`(功能完成待部署)/ `已设计`(有设计文档待开发)/ `部分完成` / `待细化`(需求未明)/ `探索/原型` / `未启动`。

## 阶段性里程碑(每周期末,每条是一个"达成的结果")

### C4 末 · 基础建设与能力增强(2026-08)
- M4-1 多租户隔离与数据正确性红线全部清零,跨租户/越权风险消除,新能力可安全上生产
- M4-2 Milvus 内存不再耗尽、collection 可 offload,集群版具备水平扩展能力
- M4-3 检索准确度提升一档:专有缩写/热词召回准、跨 dataset 检索有全局排序
- M4-4 CSRS 管理系统三站点上线、Slack 7 个知识域问答投产,内部可用
- M4-5 cognify 地基夯实:ontology 抽取规则可用、线上文档基线建成、解析性能与超长页问题解决
- M4-6 活文档与代码一致性可自动校验,过时文档自动告警,文档不再靠手工追

### C5 末 · 效果提升(2026-10)
- M5-1 记忆召回质量达标:多轮指代准、scope 不漏记忆、新旧矛盾记忆不再同时召回
- M5-2 图谱抽取准确率较基线可量化提升,脱离 gpt-4.1 依赖
- M5-3 多模态解析可用:图/表/扫描件按类型自动选最优引擎
- M5-4 用户可自助重切/增改 chunk,召回质量人工可干预
- M5-5 Google Doc/内部 wiki 可直连入库,同 URL 二次入库自动覆盖
- M5-6 检索精度二次提升:候选保送 + 动态权重 + rerank 生效
- M5-7 Neo4j 性能边界量化,扩展或换库结论明确;双 Agent 自动 code review 投入日常

### C6 末 · 高级特性应用与场景扩展(2026-12)
- M6-1 记忆生命周期激活:遗忘/巩固/时序/归纳上线且 PG-Milvus-Neo4j 数据一致
- M6-2 记忆检索延迟下降:去重 embed + 多路并发召回生效
- M6-3 图谱结构干净:实体按租户隔离、Neo4j 瘦身、EntityType hub 膨胀消除
- M6-4 音视频等多模态内容可被检索召回
- M6-5 容灾就绪:四存储可备份恢复、关键节点可故障切换、有高可用 runbook
- M6-6 自进化闭环原型跑通:能自动发现问题 → 归因 → 给出方案
- M6-7 AGL 过程性评价需求落地、基于 ontology 的企业培训助手用例打通
