# 面试官表现复盘 — 数据团队 AI 方向

- 录音时长：49 分钟
- 岗位方向：数据团队（数仓建设 + 数据处理 + RAG/自然语言问答类 AI 产品）
- 来源：https://api.plaud.cn/file/share/e93b1784787520684
- 候选人背景：数据开发，主讲了一个基于本体论（用 OWL/RDF 描述数仓元数据）的 Text to SQL 项目

## 做得好的地方

1. **用具体业务场景做现场推演**。没有停留在听候选人讲架构，而是抛了一个真实场景（"企业员工学了一门课，管理员问这门课学习情况怎么样，你怎么建模、怎么串起来"）让候选人现场走一遍方法论。这类问题能把背方案的人和真做过的人区分开。
2. **追问有韧性，穿透到了矛盾点**。候选人先说"查询过程不会用到本体"，你没有放过，连续追问"那建模是什么时候用到""它什么时候会用到呢"，直到候选人把流程理顺、承认查询阶段其实通过接口用到了本体沉淀的知识。这个矛盾如果不追，候选人的真实理解深度就被掩盖了。
3. **用对比性问题考本质**。"我把表的 schema 和元信息直接给大模型也能分析，为什么要引入本体？"这个问题直指技术选型的必要性，逼出了候选人第一版 JSON 元数据方案的演进史——这段是整场面试里候选人最有说服力的回答。
4. **岗位介绍诚实具体**。明确讲了团队两块工作（传统数仓建设与数据处理、RAG 和自然语言问答类 AI 产品），没有过度包装。
5. **对候选人的核心关切给了真实回应**。候选人明确说离职主因是值班影响健康，你没有承诺"我们不值班"，而是说"线上出问题还是需要处理的，我们能做的是控制线上质量"。诚实的预期管理比顺着说好，避免入职后的心理落差。

## 需要加强的地方

1. **一次抛出两个问题，第二个丢了**。"我有两个问题，第一，什么情况下会用到推理能力；第二，你们会给大模型哪些信息"——候选人只答了第一个，第二个再没被拉回来。改进：一次只问一个，问完追完再问下一个；如果候选人漏答，当场补一句"刚才第二个问题你还没答"。
2. **问题过长、句子反复重启**。多处提问带着大段铺垫和改口（"我我我问个问，就是我或者我们问一个我们问一个实际的问题吧"）。候选人有几次答非所问，部分原因是问题本身不够聚焦。改进：先在心里把问题压缩成一句话再开口，铺垫控制在一句以内。
3. **考察维度集中在单一项目，岗位核心技能没验证**。49 分钟基本全部花在本体/RAG 这一个项目上。岗位介绍里你自己提到 Flink 和数仓建设，但 Flink 只在你口中出现过一次（候选人一句"对对对"带过），数仓建设能力（建模方法、分层、口径治理的实操）没有独立考察；行为面（跨团队协作、冲突处理、推动他人）完全没有覆盖；也没有现场写 SQL 或白板推演这类硬验证。改进：50 分钟的单面预留结构——25 分钟项目深挖、10 分钟岗位核心技能验证、10 分钟行为面、5 分钟反问和收尾。
4. **替候选人总结、给答案的次数偏多**。"你们的 T-Box 其实是表、关系建的是 R-Box，是这意思吗""所以是把数据仓库相关的信息用本体表示出来了"——这些总结帮候选人理清了表达，但也把关键概念替他说了，他只需要说"对"。无法区分他是真懂还是顺着附和。改进：把总结句换成开放句，"你们的类和关系分别对应本体里的什么概念？你来讲"。
5. **两次追问"什么场景真正用到了推理"都没拿到实例，最后放过了**。候选人反复讲推理机、公理、一阶二阶关系这些名词，但始终没给出一个真实发生的、非推理不可的案例。这是判断"本体是真需求还是简历工程"的关键证据，值得逼一句"举一个你们线上真实发生的例子"。
6. **收尾没有下一步和时间线**。"我们今天就先这样，好的谢谢"就结束了，没有告诉候选人后续流程（几轮、大概什么时候有结果）。对候选人体验和雇主品牌都是减分项，一句话就能补上。
7. **薪资问题的时机可以但衔接突兀**。"等我，不好意思，我再问最后一个，你现在的薪资是什么样子"——放在最后是合适的，但已经说了"没有其他问题了"又折回来问，显得像临时想起。改进：把薪资、到岗时间这类信息统一放进收尾清单，说"最后了解几个基本信息"再一起问。

## 一句话总结

下一场最该改两件事：提问瘦身、一次只问一个；把时间结构切开，留出岗位核心技能验证和行为面，不要让候选人最熟的单一项目占满整场。
